# `selection.rs`

**Serve the best copy already in the account.**
PURE `plan_selection_repoints(owned, selection, present, rules, prefs)` + idle-gated executor `repoint_to_better_copies(store, read_activity, idle_window, hidden_ids, current_data, rules, prefs)` (`RepointRules { max_resolution, allow_resolution_downgrade }`), called by the scan loop after `dedup_owned`: a `selection` slot moves from the copy it serves (present, settled, owned) to another present `Verified` owned copy of the same title that supplies it — an episode it lists in `provides` with an emittable video file (`vfs::emittable_video_files`, matched on the file's FIRST episode code via `vfs::episode_of_file`, so a multi-episode file is never a repoint target for its later episodes; this is conservative, since the VFS keeps such a file visible while any slot selects it), or a movie's largest emittable video file — at a STRICTLY higher `release::quality_rank` (best rank, then score, then smallest hash).
Both the served copy and each candidate are ranked by the file they serve (`served_rank`): the record's rank, capped on each axis by the resolution and source tier the file's own name tags, else by the nearest directory that tags one (a repackaged pack may tag only its season folders; a directory's cam word is ignored, since in a folder it is likelier a title word such as `Body Cam/`, and so is a directory's bare `web` word when nothing else in its name is a release tag (no year/SxxEyy/Season anchor, resolution, codec or other source tag: `release::web_source_is_a_title_word`), as in `Web of Lies/`), while an axis tagged nowhere keeps the record's, and counted checked only for an MKV/MP4 file.
A standard-definition source tag (`sd_hints`, read per alphanumeric token, so `MyDVDCollection` tags nothing and an `HD` token before `DVD` makes it HD DVD) counts, in `served_rank` only, as at most 576p when the same name tags no resolution: DVD (`DVDRip`, `DVD-Rip`, `DVD`, `DVDR`, `DVD5`, `DVD9`, `DVDRemux`/`DVD.REMUX`), PDTV, SDTV, DSR/DSRip, TVRip, VHSRip, plus HDTV/HDTVRip and the XviD/DivX codecs (scene naming leaves the resolution off only an SD release).
DVD, PDTV, SDTV, DSR, TVRip and VHSRip, a DVD remux included, also count as the lowest source tier (0), while HDTV keeps its tier and XviD/DivX tag none.
So a scene `show.s05e01.dvdrip.xvid-grp.avi` or `show.s01e01.hdtv.xvid-lol.avi` in a pack recorded 1080p BluRay serves at 576p and never takes a better single's slot or makes it redundant in dedup.
`release::parse` still reads `DVDRip` as no source and no resolution, so acquisition ranking and recorded qualities are unchanged.
An account-mirror record's quality comes from its largest file, so a mixed-quality pack (1080p BluRay MKVs plus a 480p DVDRip `.avi`) never takes a slot with a worse file, whether the file's name or its season folder tags it, and a slot already on such a file moves to a better copy.
A copy tagged only with other audio languages never takes a slot: `release::wrong_audio_language` on its torrent name, file name and the directories above the file, under the acquisition prefs with `AUDIO_LANGUAGE` resolved from the title's recorded languages (the served record's, else any owned record's).
The upgrade engine applies the same test before staging.
Under the default `AUDIO_LANGUAGE=original` it is inert for a title with no recorded language, while an explicit `AUDIO_LANGUAGE` applies it to every title, as in acquisition.
Besides this pass, slots are written only by `observe` and the upgrade engine.
`record_mirror_owned` never writes one, so before this pass a better pre-existing or re-added copy stayed hidden behind a worse engine copy's slot.
Mirror copies get slots from this repoint, from upgrade swaps whose replacement inherits mirror (empty) provenance, and from `plan_missing_episode_slots`: a show episode with no slot that two or more present `Verified` owned copies supply (each lists it in `provides` and has an emittable video file whose first episode code is it) gets a slot on the best of them, by the same ranking and the same wrong-language and ceiling filters, while a movie never gets one (the VFS shows one copy of a film without a slot).
A chosen multi-episode file gets the slots of its later episodes too (as `observe` slots every episode a file carries), and a show whose copies' episodes all have slots is skipped before its files are scanned.
Without it the VFS listed such an episode once per copy for good: on 2026-11-12, copies that a dedup bug had deleted were re-added by hand and adopted by the mirror with no slots, and two shows listed 28 episodes twice.
Nothing is deleted; a slot serving an absent/unsettled copy is left to the VFS fallback; repair-hidden torrents aren't candidates; an empty listing plans nothing; each write is a compare-and-set (`Store::create_selection_if_absent`, `Store::repoint_selection_if`) so a concurrent upgrade swap, `observe` write or dedup clear wins.
Two exceptions keep it from undoing the upgrade engine: a slot serving a checked copy moves onto an unchecked one only for a strictly higher resolution, and with `ALLOW_RESOLUTION_DOWNGRADE` on no slot moves onto a copy above `MAX_RESOLUTION`.
A movie slot never moves onto a multi-film collection (`tasks::is_multi_feature_collection`), and a movie slot serving one stays there, because the VFS shows every selected film of the slot's torrent and moving the slot off would hide the collection's other films.
Dedup and the upgrade engine leave such titles alone too.
Every repoint raises the slot's per-file rank, so it converges.
A slot whose title has no other copy, or a candidate whose record rank does not beat the served file, is skipped before any file lookup or parse; this is exact because `served_rank` never exceeds the record rank.
A candidate's emittable video files are indexed once per plan, on its first lookup (`FileIndex`: the largest file overall, and the largest per first episode code), so a pack offered for many slots is not rescanned for each one.
`served_rank` and `takes_slot_from` are `pub(crate)`: dedup uses `served_rank`, `observe`'s pack gate `takes_slot_from` (which wraps the private `unchecked_may_displace`).
So are `title_language_requests`, `title_audio_prefs` and `copy_tags_wrong_audio`, which dedup shares for its audio-language test.
