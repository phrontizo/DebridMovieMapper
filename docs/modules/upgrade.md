# `upgrade.rs`

Daily quality-upgrade/downgrade + full-season consolidation engine (SP3).
`run_upgrade_once` visits every owned title each pass, except a title with `Manual` provenance (never auto-managed, M-1, its mirror and engine copies included) and a title whose representative owned record (its lexicographically-first hash) is not yet `Verified`; that title waits, all its copies included, until the record settles.
It takes one provider listing per pass, before it builds the queue, and does nothing on a failed or suspect one (`tasks::listing_is_suspect`).
Only owned copies in that listing, or `Pending` ones, count as a title's.
A title with none is stamped (no scrape or TMDB call) and left out of the queue, so it takes no `UPGRADE_BUDGET_PER_TICK` slot and isn't counted in the `visiting N of M` log line.
Only a title's present copies can make it one needing attention (`needs_attention`).
For a title with some copies absent, the handlers baseline, swap and prune among the present ones (`try_upgrade_show`/`try_consolidate_show` take the absent list) and leave absent records to the mirror reaper and the reconciler.
A copy deleted while the pass runs is caught at the swap: `apply_upgrade` and consolidation check presence again against the listing they fetch for the prune.
If none of the copies the swap replaces is still listed (what it prunes, plus what its slots serve now), the staged candidate is rolled back and nothing is pruned.
`apply_upgrade` then returns `SwapSkip::Gone` (its own outcome type, which has no `Busy`, since a swap adds nothing): the movie path stamps the cursor, phases (1)/(2) move to the next episode and pack correction moves to the next pack.
Consolidation moves to the next season.
So the pass never adds back a release for a copy the user deleted or that lapsed.
`rank_changes` and the candidate loops of pack correction and consolidation skip any owned hash, of this title or another, so an absent copy is never staged again and staging never overwrites another title's record.
`apply_upgrade` defers, slots untouched, when the staged copy is no longer owned before it repoints them.
Titles holding a copy of unknown or unchecked quality go first (`needs_attention`/`upgrade_batch`; `UPGRADE_BUDGET_PER_TICK` caps the pass); a title with a copy being read is skipped for that pass (cursor unchanged) and the pass carries on, and every staging site and swap re-checks just the torrents it would delete or take a file away from (`copies_serving`/`copies_behind_slots` → `being_read` → `ReadActivity::torrents_idle`), so a read of another title never holds a swap back; right before dispatching a title it runs the TMDB language backfill (`LanguageBackfill::run`) — when ANY owned record of the group (not just the representative: the show paths stage and probe with each episode/pack record's own request) has `request.spoken_languages == None` (legacy/mirror), ONE TMDB `details` call fills every record's unset language fields (`persist_title_languages` → the atomic `Store::backfill_title_languages_if_unset`, which touches only `spoken_languages` and — when unset, as on an account-mirror record — `original_language`, so a concurrent `observe` write can't be clobbered and a mirror title's staging probe checks `original ∪ spoken` like an engine-acquired one); once every record is `Some` (even empty) the group is never re-fetched.
A **transient** TMDB failure (5xx/429/transport) **defers** the title (`UpgradeSkip::Deferred`, cursor unchanged, retried next tick) instead of probing with the original-only rule — which could blacklist correct spoken-language releases for the 30-day blacklist TTL — and later titles needing a backfill that tick are deferred without another fetch (an outage costs one retry cycle per tick, not one per title); a **permanent** 4xx (an unknown id, `tmdb_client::error_is_permanent`; a rejected key, 401/403, is transient and defers) proceeds with the recorded languages so the title isn't parked at the head of the round-robin forever.
Under `AUDIO_LANGUAGE=original`, a title with no language recorded at all after the backfill (`AcquisitionEngine::audio_unchecked`, e.g. an account-mirror record TMDB refused) is skipped (`NoChange`, cursor stamped), since no staging probe could check its audio.
Every staging site also treats a probe `Pass` that checked no audio language as `Accept` (`staging_probe`).
Both TMDB lookups are injected (`run_upgrade_once_with(app, fetch_details, fetch_aired)`: the language backfill's `details` and consolidation's aired-episode set, passed through `try_upgrade_show` to `try_consolidate_show`), so the backfill and the whole show visit are tested offline.
Titles then go through a shared `rank_changes`/`apply_upgrade` core: `rank_changes` scrapes and ranks ALL candidates via `is_target_improvement` against the owned baseline, best-first — improvement is judged on the RAW prefs (like every stored `QualitySummary` score, so stored and fresh scores compare like-for-like: no flip-flop) AND again with the candidate scored under the title's audio-resolved prefs (`ordering_prefs` → `with_resolved_audio(original_language, spoken_languages)` from the group's request, exactly as acquisition ranks), so a release acquisition would rank BELOW the owned copy — e.g. a raw-prefs category jump that, tagged `Rus`/🇷🇺 on an English-original show, carries the wrong-language penalty — is never staged (where untagged audio tracks would let it pass the probe); against an unknown-quality (or uncached) owned copy, where `is_target_improvement` ignores scores so that second test can't see the penalty, a release carrying it (`release::wrong_audio_language`, the predicate `score` penalises on) is dropped outright; the penalty only lowers the candidate's score, so the second test is strictly stronger and every swap still raises the raw score.
The improving candidates are ORDERED by `release::rank_key` under those prefs (resolution and the language penalty, then a tagged source before an untagged one, then the score), as acquisition ranks them, so under `AUDIO_LANGUAGE=original` a wrong-language-tagged release is staged after a correctly-tagged one instead of first, and a corrective downgrade adopts an untagged-source release only when no tagged one at its resolution qualifies; the pack rankers (`rank_cached_pack_candidates`, for pack correction + consolidation) are called with the same resolved prefs, order packs best first in acquisition's order (`release::rank_key`: resolution, then a tagged source before an untagged one, then score), and drop a pack carrying the wrong-language penalty (`release::wrong_audio_language`) outright, since both judge a pack on tier and resolution only (`rank_changes` also drops such a candidate for a corrective `Downgrade`, whose ceiling penalty swamps the language one) (an `Upgrade` always proceeds; a `Downgrade` — an owned copy sitting above a since-lowered `MAX_RESOLUTION` ceiling — proceeds only when `ALLOW_RESOLUTION_DOWNGRADE` is set, otherwise it is preview-logged and skipped).
A corrective downgrade on the movie path or in phase (1) never goes below the highest within-ceiling resolution already owned (`within_ceiling_floor` / `drop_downgrades_below`); pack correction (3) has no floor.
When a group also owns a within-ceiling copy of unknown quality (e.g. a 1080p file with an untagged source), its over-ceiling copy of known quality still sets the baseline, so every lower within-ceiling candidate would otherwise read as a `Downgrade`, and the movie swap would then prune the 1080p copy too.
On the movie path the floor is taken over all owned copies; in phase (1) over the singleton and the copy its slot serves.
Both the **movie** and **per-episode** paths try the ranked candidates in order until one stages successfully (in-tick fall-through — the same pattern the pack-correction and consolidation loops already use — so a structurally-unusable top candidate, e.g. a pack missing the target episode, no longer blocks the slot; a gated-off downgrade still stops the whole list, since it is direction-homogeneous), then `apply_upgrade` stages the winning CACHED release, idle-gated swaps the `selection` slot(s), and prunes the superseded torrent(s).
For a movie that is every within-ceiling owned copy of the film (`supersede_hashes`; an over-ceiling copy too only with `ALLOW_RESOLUTION_DOWNGRADE` on), so an adopted movie upgrade leaves one copy of the film whatever `DEDUP_REMOVE_DUPLICATES` says.
Both swap paths, `apply_upgrade` (movie, per-episode, pack-served and over-ceiling pack correction) and full-season consolidation, prune through `prune_behind_staged`, which prunes the superseded copies only while the staged copy's owned record still exists: if dedup removes the just-staged copy after its fresh-title skip (`UPGRADE_IDLE_SECS`) has run out, the old copy is kept and the swap defers.

**Upgrades adopt only checked releases:** every staging site (movie `stage_and_verify`, per-episode `stage_episode_candidate`, pack correction, consolidation) adopts only a probe `VerifyResult::Pass` — an `Accept` (tracks couldn't be checked) deletes the staged torrent and moves on (`NoChange("unverifiable release")` / next candidate) **without** blacklisting it, and `rank_changes` / `rank_cached_pack_candidates` skip a candidate whose addon-reported file name is known and isn't MKV/MP4 (`known_unverifiable` — it could never pass), so an upgrade never swaps a checked copy for an unchecked one; an owned copy flagged `quality.unverified` is replaced by an equal-or-better checked cached release (see `is_target_improvement`), and every staged record's `QualitySummary::of` snapshot is `unverified: false`.
All four share one staging head, `stage_and_await_cached` (add, select, cached poll; `FileSelection::LargestVideo` for a film, `AllVideos` otherwise), and one pair of gates, `check_staged` (the title check, then `staging_probe`).
A deferred probe defers the movie title, moves the per-episode path on to the next episode, and moves pack correction and consolidation on to the next candidate pack.
Every staging site records the adopted copy through `record_staged`: if the owned or authoritative write fails, the staged torrent is deleted and nothing is swapped or pruned.
The movie path then defers the title, consolidation defers for the rest of the show (like any consolidation deferral) and pack correction the show visit, while on the per-episode path (phases (1) and (2)) `upgrade_episode_slot` maps the `Deferred` to `EpisodeUpgrade::Unchanged`: that episode is skipped for this pass and the visit carries on, its cursor stamped unless something else defers.
A title check with no verdict (`TitleCheck::Unavailable`, TMDB unreachable) is a deferral too: the staged torrent is deleted and not blacklisted.
Every staging site title-checks the in-torrent path and the torrent name (`acquire::torrent_name_of`).
Pack correction and consolidation read a staged pack with `vfs::show_episode_files`, as `observe` and per-episode staging do, so a code-less pack under an explicit season is adopted with every episode in `provides` and a slot on each file.

**Never stages a candidate already in the account:** every staging site adds through `add_staging_candidate`, which checks a fresh provider listing immediately before the add (one extra full `get_torrents` per staged candidate — a paged listing, ⌈N/100⌉+1 requests on Real-Debrid and ≥2 on TorBox, through the provider's shared rate limiter; staging is rare — only an improving candidate is staged, daily, within the title budget — and consolidation skips a pack below an owned episode's tier/resolution before staging it) and skips (`NoChange` → next candidate) a hash whose torrent is already present — every site deletes a rejected/rolled-back candidate by the id the add returned, and on TorBox an add of a present infohash returns the EXISTING torrent's id.
The rankers already skip every hash owned under any title, so this check covers a present torrent no owned record names (an unidentified manual add, or one the account mirror hasn't recorded yet), which would otherwise be deleted or adopted as a staged copy; a listing failure is `Deferred` like an add failure (nothing is added), and so is a suspect empty listing (`tasks::listing_is_suspect`: empty while identifications are cached, which TorBox can answer as a glitch).
Against such a listing every hash reads absent, and on TorBox the add of a present hash returns that torrent's id, which a rejection would then delete.
Every staging add first claims a staging intent (`Store::claim_staging_intent`): a failed intent write defers.
A hash another stager holds is not staged (`NoChange`), and neither is one recorded as owned since ranking (re-read from the store after the claim, because TorBox's listing can lag an acquire's add, and staging would return that torrent's id and could delete it).
A failed add closes the intent again; an add the provider reports busy (`provider::is_provider_busy`) is `UpgradeSkip::Busy`, which every staging site passes up so `run_upgrade_once` ends the pass with that title's cursor unstamped (no other title, episode or pack is staged that pass).
The returned torrent id of a successful add is recorded on the intent.
`record_staged` closes the intent.
Every rejection or rollback before the candidate is recorded deletes it through `discard_staged`, which closes the intent only once the delete succeeded.
`sweep_staging_intents(store, provider, listing, now)` (called by the scan loop) deletes what a cancelled or panicked job left behind.
It keeps an unlisted intent open until deleting its torrent id succeeds or it is `STAGING_LISTING_LAG_SECS` (600 s) old.

**A 404 on the staged torrent's lookup is retried:** right after the add, every staging site looks the torrent up through `staged_torrent_info`, which retries a 404 after 1, 2, 4 and 8 s (`STAGED_INFO_BACKOFF`, 15 s at most) before giving the candidate up (deleted, then `Deferred`, or the next pack in consolidation and pack correction).
TorBox's `mylist?id=` sometimes answers 404 ("No torrents found for this user") for a torrent that exists, often one `createtorrent` has just returned: on 2026-11-13 it did so 21 times in ten minutes, and the 15 that hit a staged torrent's first lookup deferred 15 episode upgrades (the four that hit `await_downloaded`'s polls cleared on the next poll a second later).
Other errors aren't retried there, since the provider clients already retry transport errors, 429s and transient 5xx.
**A replacement inherits the provenance of exactly the copies it supersedes** (`superseded_provenance`): the singleton's in phase (1), the serving pack's in phase (2), the old pack's in pack correction, the in-season records the prune supersedes in consolidation, and the `supersede_hashes` set for a movie.
It is EMPTY (account-mirror semantics) as soon as one superseded copy is a mirror record, so upgrading the user's own copy never turns it into an engine copy that Trigger B could delete.

**Only settled copies are upgraded:** within a title that passed the representative-record check above, phases (1)/(2)/(3) consider only `Verified` records, consolidation skips a season while a `Pending` record supplies it, and the movie path defers a film while any copy is `Pending` (`observe` owns it, and its uncached acquire-time quality would make any cached release read as an upgrade, at any resolution).
A multi-film collection (`tasks::multi_feature_hashes`) is never upgraded by the movie path: `try_upgrade_movie` returns `NoChange` before scraping.
**Shows** get the same treatment at four layered stages per tick: (1) **per-episode** upgrade/downgrade — every owned singleton episode is re-scored and swapped independently, against the better (`best_owned_quality`) of the singleton's own quality and the owned copy its slot currently serves, since the swap repoints that slot (so a slot served by a better pack is never moved to a candidate that beats only the singleton; the baseline also counts a copy adopted for the same slot earlier in the tick); (2) **pack-served episode upgrade** (phase a2) — for every owned **within-ceiling** multi-episode pack (`provides.len() > 1`; a pack with no recorded quality counts as unknown on both axes), each episode whose `selection` slot points at the pack is re-scored against the **pack's** quality and, on a better cached **true singleton** that is also no regression vs the pack on either axis (`pack_split_no_regression`: candidate source tier AND resolution ≥ the pack's — the per-axis test `consolidation_target` applies, filtered before the sample-first check, so a pack is never split into singles below it on either axis; an UNKNOWN pack axis (0) is the lowest, so any known candidate passes it.
No pass undoes another: (1) and (2) only ever move a verified copy UP a category (`is_target_improvement`: a higher resolution, or a higher tier at the same resolution; only the one-shot unverified rule can do otherwise, and every adopted copy is verified), so singles (2) split from a pack — at least the pack on both axes, above it on one — never come back down to where (4)'s no-regression gate could re-adopt that pack.
Before the same-resolution tier rule, (1) swapped the BluRay x264 singles split from a WEB x264 pack for higher-scoring WEB x265 ones and (4) folded those back into the pack, every two visits; an equal-tier/resolution split can only come from the unverified rule, and (4) re-adopts a pack only on a probe `Pass`, recording it verified, so such a pack is split + folded back at most once), swapped exactly like (1) (same stage/probe/idle-gated `apply_upgrade` path — phases (1) and (2) share `upgrade_episode_slot`, differing only in `EpisodeSupersede`: a singleton is pruned outright, a pack only via `pack_prunable_after_repoint`).
The pack is **pruned only on the repoint that leaves it serving no slot AND with every episode it provides held by another `Verified` owned record of the show whose torrent is still PRESENT** — `other_owned_coverage` re-reads the store just before the swap (so singles staged/pruned — or an overlapping pack pruned — earlier the same tick count, and a `Pending` copy, still reapable, does not), and the decision itself (`PrunePlan::Pack` → `PackPrune::resolve`) is settled inside `apply_upgrade` against the provider listing it fetches before its final read check: a `Verified`-but-absent (lapsed) record does not count (the VFS falls back to the pack for that record's stale-selection episode, so deleting the pack would lose the episode with nothing to bring it back — no file left to read for on-read repair), while a single adopted earlier the same tick counts as present even before the listing shows its add (`EpisodeTick::adopted`); otherwise the pack is kept.
Only selection-served episodes are considered (a mirror pack with no managed selection is left alone; the selection pass gives a mirror pack's episodes slots when another present copy also holds them, `selection::plan_missing_episode_slots`, and from then on they count as served, so such a pack can be split and pruned like an engine one).
No show swap prunes a copy holding a video file with no episode code that its record doesn't account for (`copies_holding_codeless_files`; a code-less file that `vfs::codeless_episode_files` maps to an episode in the record's `provides`, as in an engine copy of an absolute-numbered single or of a code-less pack under an explicit season, is accounted for, so such a copy is pruned like any other.
It reads the persisted identifications only when a prune is at hand; a copy with no persisted identification is judged by its record): phases (1) and (2) move the slot and keep the old singleton or pack, consolidation leaves such a copy out of `superseded` (it is not pruned and doesn't count for the new pack's provenance), and pack correction (3) skips such an over-ceiling pack before scraping, since keeping it beside a replacement would stage another pack on every visit.
Sample-first cost bound: if the pack's first served episode yields no improving candidate (or its scrape fails), the rest of that pack is skipped this visit; and phases (1) and (2) drop, before ranking, every stream whose torrent name plainly names several episodes (`is_pack_stream`: an episode range, two or more episode codes, or a season token such as `S01`, `Season 2` or `S01-S03` with no episode code, no episode word (`E05`/`Ep 5`/`Episode 12`) and no trailing ` - NN` number), so a season pack named as one is never staged by the per-episode phases.
A candidate that stages as no single anyway (a multi-episode torrent whose name doesn't say so, such as `Show Complete Series`, or one with no file that maps to an episode, such as a multi-file pack of absolute-numbered `Show - 05.mkv` files with no explicit season; per-episode staging reads episodes as acquisition does, `vfs::show_episode_files`, so a single-file absolute-numbered release is a single and is adopted) is staged at most once per show tick (`EpisodeTick::not_singles`, shared with (1): Torrentio lists the same season pack under every episode query and the per-episode path never adopts one), not once per served episode.
From then on it counts as no improving candidate, so a pack whose sample episode improves only on such torrents is skipped the same way: one scrape and at most one staging.
A hash adopted earlier the tick is never re-staged either.
Over-ceiling packs are left to (3).
Dedup cooperates: its second sweep removes a copy only in favour of same-or-better-quality coverage, so when a kept pack is the sole holder of some episode the better singles it also covers are kept (the quality-agnostic sweep that used to delete them — the 2026-11-11 regression — is gone).
This is what replaces an air-date grab like an SD foreign-dub pack serving one episode of an otherwise-1080p season; a lower-quality full-season pack may be split into better singles, which (4) later folds back into a pack only when one at least as good on tier and resolution exists (never the split pack itself, bar the one unverified re-fold above); (3) **over-ceiling pack correction** (`correct_over_ceiling_packs`) — an owned season pack above the ceiling is replaced by the best within-ceiling CACHED pack covering the same episodes, with no `within_ceiling_floor` (the selection repoint later moves a slot to a better within-ceiling copy the show owns; see `ALLOW_RESOLUTION_DOWNGRADE`) (it repoints only the slots the old pack served, or that have no selection, so a slot serving another copy keeps it, and records the replacement's `provides` as every episode it holds; same downgrade gate; a sole over-ceiling pack with no conforming replacement is kept, never deleted; its candidates exclude every hash the show owns at that point — re-read from the store, so a single adopted by (1)/(2) earlier the tick is never re-staged and then, on TorBox whose re-add returns the SAME torrent id, deleted by the coverage-miss cleanup); (4) **full-season consolidation** (`consolidation_target`; a show with no season that has a single-episode record and at least two records supplying it (packs included, `season_has_scatter`), e.g. one held only as packs, skips the TMDB aired-episode lookup; the injected lookup returns `tasks::AiredEpisodes`, and a complete lookup listing no aired regular episode is `NoChange`, cursor stamped, while only a failed lookup that found nothing defers) — scattered per-episode torrents are merged into a CACHED full-season pack covering every aired episode at same-or-better quality (its tier/resolution no-regression half, `pack_no_regression`, is checked before staging too, so a candidate below an owned episode is never added just to be deleted; an unknown axis — 0, or no recorded quality — is the lowest on either side: an owned episode's unknown axis never blocks a pack, a pack's unknown axis is a regression against any known episode axis).
A copy adopted earlier in the same visit by (1), (2) or (3) (`ShowEpisodePass::adopted`: its hash and the torrent id its add returned) counts as present even while a lagging TorBox listing doesn't show it yet.
When consolidation folds it into the pack, it is deleted by that id (`prune_behind_staged` → `prune_owned_hash_in`), and its records are dropped only once that delete succeeds.
A single-episode stream (one episode code and no episode range in the torrent name, or no code but a trailing ` - NN` number (`[Group] Show - 05 (1080p)`; a batch `- 01-12` has none), the torrent name being the first line of the stream description: `is_single_episode_stream`, which treats the range names `S01E01-E10`, `S01E01-10`, `S01E01-S01E10` and `S01E01~E10` as packs.
The `NxM` and separated ranges (`1x01-10`, `1x01-1x10`, `S01.E01-E10`) count as packs too, since `parse_se_all` leaves them undecoded or reads both endpoints; `EPISODE_RANGE_RE` itself covers only the contiguous `SxxEyy` form) is never staged as a pack, here or in pack correction (both rank through `rank_cached_pack_candidates`), and a candidate that staged and turned out multi-season or missing an aired episode is remembered for the process's life (`NOT_SEASON_PACKS`, per `AppState`, kept out of the acquisition blacklist) and not staged again.
Consolidation is never a downgrade path — it never trades quality.
**Unknown quality = lowest everywhere** (`release::is_unknown_quality` / `quality_rank`): an owned copy with no recorded quality (baselined as `QualitySummary::unknown()`) or an untagged resolution/source tier is improved by any known-quality cached within-ceiling candidate that passes the probe, at or above its resolution when that is tagged (a known resolution stays a floor, so this ungated path never trades resolution down; movie baseline `best_owned_quality` = known before unknown, then `effective_score`, except that an unknown within-ceiling copy at a higher resolution than that pick baselines instead; per-episode singleton; pack-served (2); consolidation), never by an unknown one, and a known copy within the ceiling is never "improved" by an unknown candidate — the swap records the adopted release's known quality, so a second visit changes nothing (converges).

**Hard constraint:** a copy whose file name shows a resolution **above** `MAX_RESOLUTION` is never unknown-lowest, whatever its source tier — `is_unknown_quality` exempts an over-ceiling resolution, `run_upgrade_once` first re-derives any `quality: None` record's quality from the persisted identifications, and heals an account-mirror record whose untagged resolution or source tier its file names now tag (`tasks::backfill_owned_quality`, run on every pass), and mirror records now store an over-ceiling file's real resolution (`QualitySummary::of_owned`) — so it stays under the corrective-downgrade rules and `ALLOW_RESOLUTION_DOWNGRADE`.
A mirror record (`Verified`, empty provenance, no quality, no `provides`) whose listed torrent lists no video file is dropped by the scan loop's mirror pass and mirrored again once its files are back.
Any other record whose torrent lists no video file stays `None` (and is unknown-lowest).
