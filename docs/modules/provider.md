# `provider.rs`

`DebridProvider` trait abstracting the debrid backend; `FileLocator` (the provider-neutral handle for a media file) and its `resolve_url`/`invalidate` primitives; startup provider selection (`choose_provider`); test-only `MockProvider` (its `resolve_by_link` knob makes `resolve_url` return the locator's own link); `torrent_info_retrying_not_found` (a `get_torrent_info` that retries only a 404 after each given wait; used by the instant repair, `reacquire::materialise` included, with `repair::REPAIR_INFO_NOT_FOUND_BACKOFF` (0.5 s / 1 s), and by upgrade staging through `upgrade::staged_torrent_info` with `STAGED_INFO_BACKOFF` (1/2/4/8 s); it is `pub`, so the live `integration_test` and `repair_integration_test` use it too, with the 1/2/4 s `common::INFO_NOT_FOUND_BACKOFF`); `DeleteTracker` (counts the clients' own deletes, started and in flight, so a paginated listing can tell when one may have shifted its pages and dropped a live torrent), `MAX_LISTING_ATTEMPTS`, `READ_PATH_REQUEST_TIMEOUT`; `provider_busy_error` / `is_provider_busy` (the 429 an add returns when the provider took it but won't start it, i.e. TorBox's queued add, or throttling; `acquire` stops adding on it and returns `AcquireOutcome::ProviderBusy`, after which `reconcile_wanted` and `monitor_episodes` add nothing more that run (`tasks::BusyProvider`), and a busy upgrade staging add ends the upgrade pass (`UpgradeSkip::Busy`)); test-only `MockProvider.add_magnet_busy`
