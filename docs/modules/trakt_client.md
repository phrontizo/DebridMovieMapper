# `trakt_client.rs`

`TraktClient` trait — device-flow OAuth (`device_code`/`poll_token`/`refresh`; a 5xx on the device-token poll, after `send_with_retry`'s short budget, is returned as `AppError::Upstream` so `poll_to_completion` retries it under its consecutive-error cap instead of treating it as an expired code; a 404 (invalid code), a 409 (code already used), a 401/403 or any unlisted poll status is `DeviceTokenPoll::Rejected(status)` (only 410 is `Expired`), which enrolment reports as "Trakt device-token poll returned HTTP {code}", with a `TRAKT_CLIENT_ID` / `TRAKT_CLIENT_SECRET` hint for 401/403 and a "start a new enrolment" hint for 404/409), reads (`watchlist`/`in_progress`/`watched`), `show_progress` (per-show `progress/watched` → `ShowProgress{aired,completed,behind}`, the precise catch-up "behind?" gate), and `me()` for the user slug — plus `TraktClientImpl` (shared adaptive rate limiter, Trakt headers) and test-only `MockTrakt`.
`WatchedShow` carries the show's Trakt numeric id (`trakt_id`) so `show_progress` can be called.
**Every list read is paginated** (`authed_get_list`): Trakt's 2026 API changes made `/sync/watchlist/{movies,shows}` (2026-04-15, trakt-api discussion #681) and `/sync/watched/{movies,shows}` (2026-07-03, #775) paginate **by default** — returning only page 1 (100 items) — so each is requested as `page=N&limit=100` (`PAGE_LIMIT`; 100 is also the cap for `extended=progress`) and `X-Pagination-Page-Count` is followed (`parse_pagination`); without a usable page count (missing, garbled or 0) a page 1 shorter or longer than the limit is the whole list, while an exactly full page is followed by the next until one comes back short (`warn!`ed; a server that ignores `page` and repeats page 1 fails `repeated_list_item`, and still-full pages past `MAX_PAGES` are an `Err`); more than `MAX_PAGES` (200) pages is an `Err` (no runaway loop).
`/sync/playback` does not paginate (no pagination headers live), so it is still requested without `page`/`limit`, but further pages are followed should headers appear.
`parse_playback` collapses a show's playback entries to one `TraktItem` whose `paused` lists every paused regular-run episode with its `paused_at` (a special, or an entry with no readable `paused_at`, adds none).
`parse_watched_shows` also keeps each watched episode's `last_watched_at` (`WatchedShow.episode_watched_at`).
**A failure of ANY page fails the whole read** (`Err`, never a silently truncated `Ok` — a truncated watchlist would read titles beyond page 1 as un-watchlisted → Trigger B), as do a non-array page body and a list seen to **change mid-read** (`check_page_consistency`: page/item count differing from page 1's, or the server answering a different page; `repeated_list_item`: one item appearing on two pages, keyed by `list_item_key` on its list-item `id` (watchlist and playback entries) or, on the watched lists, whose items carry none, on its `movie.ids.trakt` / `show.ids.trakt`.
This catches a reorder, including a watch that moves a title from past position 100 to the top of the newest-first watched list); `sync_trakt` then keeps the user's previous `wanted` set exactly as for any read failure.
Items shifting across a page boundary could drop a title from both pages.
One such shift is not detected: an item removed from an already-read page while another is added on a later one, between two page fetches, keeps both counts, so the first item of the next page is read on neither.
Accepted residual risk: it needs a list over 100 items and both changes inside the sub-second gap between page requests.
The read then succeeds without that title, the reconcile right after may remove its engine copies (Trigger B), and the next sync acquires it again.

**Watched shows are read with `extended=progress`:** since 2026-07-03 the plain endpoint returns NO `seasons` (`noseasons` is a no-op), which made every show's watched-episode set EMPTY — Trigger A never fired for shows, `REMOVE_FINISHED_SHOWS` logged "REMOVING" but removed nothing, and catch-up re-acquired already-watched episodes.
The `extended=progress` shape is the old one plus `seasons[].episodes[].{number,plays,last_watched_at}`; `show.ids` keeps `tmdb`/`trakt`/`imdb` (`imdb` may be `null` → `None`) and `last_watched_at` is unchanged, so `parse_watched_shows` reads it as-is; Trakt omits season 0 there.
When `reset_at` is set (the user reset the show's progress for a re-watch) an episode whose `last_watched_at` predates it is not counted as watched — matching Trakt's own per-show progress, so a re-watched Ended show isn't finish-removed mid-re-watch.
Parser tests run on trimmed **real** responses in `tests/fixtures/trakt/` (captured Nov 2026, anonymised: the shapes are exactly as Trakt sent them, but titles, ids, slugs and list-item ids are fictional and dates shifted); pagination tests use the `#[cfg(test)] test_http` loopback router (route = path + order-insensitive query; also used by the `tasks` sync tests to drive `sync_trakt` through the real client)
