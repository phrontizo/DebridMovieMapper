# `repair.rs`

Torrent repair state machine (Healthy→Broken→Repairing→Failed); provider-neutral instant repair — `try_instant_repair(&FileLocator)` re-adds by hash and, if cached, returns a fresh `FileLocator` for the same file (matched by `file_path`) for `dav_fs` to swap in (30s cooldown; a torrent is marked `Failed` after 3 consecutive cached new-id (Real-Debrid) re-adds without a good read, since only `complete_repair`'s new-id path carries the count to the replacement, while a same-id TorBox re-add and every transient or cut-short repair reset it; each repair bounded to 30 s; a repair cut short by that timeout or a dropped read resets the attempt budget and deletes a new-id torrent it added but had not adopted, `UnadoptedAddGuard`; a new-id repair records the replacement and settles the health map before the superseded torrent is deleted, from a detached task (`delete_superseded`), so a slow Real-Debrid delete can't time out a repair that already succeeded; its torrent lookups retry a 404 briefly, `REPAIR_INFO_NOT_FOUND_BACKOFF`; a new-id (RD) repair records a `redirect` from the old torrent's files to the replacement, which `dav_fs` follows on open (until the next scan rebuilds the VFS) and which `try_instant_repair` returns for a locator of the old torrent before repairing anything; `hidden_torrent_ids` (the VFS filter) holds `Broken`/`Failed`, while `should_hide_torrent` (reads) also refuses `Repairing`; `is_hidden` gives the VFS view for one torrent, and an opened file's metadata (`dav_fs` `ProxiedMediaFile::metadata`) reads it, so a file opened mid-repair keeps its real size (an empty one would answer a ranged GET with `416 bytes */0`) while its reads are refused; a timed-out or dropped repair restarts the cooldown)
