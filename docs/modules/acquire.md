# `acquire.rs`

`AcquisitionEngine` — **optimistic `acquire`** (SP3): scrape → rank → add the best non-blacklisted candidate → best-effort `select_files` for an already-cached add → record `Pending` → return immediately (no synchronous validation/probe; the verdict is deferred to `observe`).
`acquire` fetches the provider listing once before the first add and never adds a hash already in the account that the title doesn't own (on TorBox the add would return the EXISTING torrent's id).
If the listing can't be fetched it adds nothing (`TemporarilyUnavailable`).
An owned `Pending` record added no more than `ACQUIRE_DEAD_TIMEOUT_SECS` ago counts as present even when the fresh listing lacks it (`acquire::in_flight`), so a pack added for one episode answers the next episode's acquire while TorBox's listing lags, and `reap_lapsed_superseded` leaves such a record alone.
Each add first claims the hash's staging intent (`Store::claim_staging_intent`).
The claim is exclusive: while another stager holds the hash (the upgrade job, another acquire), or when the write fails, nothing is added and the result is `TemporarilyUnavailable`.
A hash not owned at the pre-scan is then re-read from the store, because a lagging TorBox listing may not yet show another stager's add.
If it is owned now, the intent is closed: a record of this title that supplies the request returns `Acquired`, and any other is skipped.
An add the provider reports busy (`provider::is_provider_busy`: TorBox queued it at the account's active-download limit, or a 429 outlasted the client's retries) closes the intent and returns `AcquireOutcome::ProviderBusy` instead of trying the next candidate; `reconcile_wanted` and `monitor_episodes` then add nothing more for the rest of their run (`tasks::BusyProvider`; removals still run).
A failed add closes it, and it is closed once the Pending and authoritative records are written; a rollback whose delete fails keeps it, so the staging sweep deletes the torrent.
An acquire cut off mid-add therefore leaves nothing for the mirror to adopt.
After adding a new hash, `acquire` drops (`reap_lapsed_superseded`, store-only, with its authoritative id and selection slots, through `Store::forget_owned`) any non-manual owned record of the exact same slot whose torrent has left the listing: a same-tmdb movie, or a singleton of the requested episode.
Packs, present copies and `Manual` records are kept.
It skips a candidate owned under another title (warn: possible misidentification), checks every ranked candidate for an owned+present copy that supplies the request before adding (`Acquired`; for a show, a copy whose `provides` lists the requested episode, or one still `Pending` or with an empty `provides`, whose coverage is unknown (for a `Verified` copy with an empty `provides`, the episode monitor remembers the answer, see `tasks::AssumedCoverage`); a present copy of the show that doesn't provide the episode, e.g. a Real-Debrid pack with only some files selected, is neither a short-circuit nor re-added; `MAX_ACQUIRE_ATTEMPTS` bounds add attempts, and candidates skipped as already in the account don't count; if the `Pending` owned record or the authoritative id can't be written after a successful add, the add is deleted again and `acquire` returns `TemporarilyUnavailable`, as the upgrade engine's `record_staged` does), and refuses a show request that names no episode (`NoAcceptableRelease`).
`fail_and_reacquire` therefore reaps a dead account-mirror show record without re-acquiring, leaving that to `monitor_episodes`.
A dead multi-episode pack is re-acquired only for the one episode its record names (the episode an acquired pack was added for, a consolidated pack's S{n}E01 sentinel, or the episode a pack-correction replacement inherited from the old pack).
The rest of the season comes back only through `monitor_episodes`, so only with Trakt configured and the show wanted.
Every mirror show record names no episode (`record_mirror_owned` writes `season: None, episode: None`), single-episode torrents included, and `monitor_episodes` runs only when Trakt is configured and only for shows someone wants.
Otherwise the dead torrent is deleted with no replacement, and its 30-day blacklist entry also stops the mirror from adopting a manual re-add of the same hash until it expires.
**`observe`** is the resolver (every scan tick): once files resolve, runs the deferred pack-guard → strict title-validation → probe (title validation is three-way, `TitleCheck::{Match, Mismatch, Unavailable}`: `Unavailable`, TMDB unreachable or a rejected key, counts no strike and blacklists nothing, so the record stays Pending and is re-checked next tick, with at most one TMDB check per tick once one comes back Unavailable; two CONSECUTIVE `Mismatch`es reject it as WrongTitle).
For a show request the file is the first selected video carrying the requested episode's code.
A selected video file with no episode code that names its episode by an episode word (`E09`, `Ep 9`, `Episode 9`; `vfs::EPISODE_WORD_RE`), a part of a total, glued (`Doc.2of4.mkv`) or worded (`Part 2 of 4`; `vfs::part_of_total`; a spaced `N of M` without `Part`, as in `Finale (1 of 2)`, is a title's own words, and a worded `Part N` names no season, in the file name or a folder) or a trailing ` - NN` number (the anime form `[Group] Show - 12 (1080p)`, `identification::trailing_episode_number`) supplies that episode (`vfs::codeless_episode_files`, merged with the coded files in file order by `vfs::show_episode_files`).
A single-file release takes the season the VFS places it in (season 1 unless its name or a directory names one, `vfs::season_of_codeless_file`).
A file of a multi-file pack counts only under an explicit season, a season token in its name or a season directory (`vfs::explicit_season_of_codeless_file`, which shares `vfs::season_of_codeless_file`'s lookup and names no season when the nearest name naming one names a season range, such as `[Group] Show (Season 1-2)` or `Show.S01-S03`); a `Part N` in the file name doesn't count.
A part of a total (`Doc.2of4.mkv`) is also mapped in season 1 when nothing names a season and the pack's parts are one run: every code-less video a part of the same total, each part once, else nothing in the pack maps.
If a mapped episode is also named by another selected video file, no code-less file is mapped.
Such a file is title-checked on its path, and the release is verified with `provides` listing every episode its files map to and a slot on the requested episode's file.
Still rejected as `EpisodeMissing` after `ACQUIRE_DEAD_TIMEOUT_SECS`, even mid-download: a multi-file pack of absolute numbers with no explicit season, an absolute number past season 1, and a pack whose code-less file names an episode another file also names.
The account mirror and `backfill_owned_provides` still read episode codes only.
Dedup (`holds_codeless_video`, and its coverage check through `tasks::accounted_codeless_files`), the upgrade engine's staging sites and the VFS selection gate read the code-less mapping too (see `docs/modules/tasks.md`).
`TmdbTitleValidator` identifies the file by its name, or, when the name carries no title of its own (`identification::names_a_title`: `E09 - Title.mkv`, `S01E05.mkv`, `05.mkv`), by the nearest enclosing directory that names one (season, part and disc folders are skipped, and so are `Series N`, `Staffel N` and other season-folder spellings), else the torrent name, which `TitleValidator::validate` and `AcquisitionEngine::validate_title` take (`acquire::torrent_name_of`: `filename`, else `original_filename`).
The rule is `identification::identification_name`, which `identification::identify_torrent` uses too.
A name that does carry a title is identified by itself, so `Other.Show.S01E05.mkv` is another show whatever its torrent is called.
A show request identifies through `identification::identify_name_with_show_hint`, so a same-titled film never wins a show's title check; the mirror and movie identification pass no hint.
The title check also requires the identification's media type to match the request (TMDB's movie and TV ids overlap).
On pass — marks `Verified`, records `provides` (which episodes the hash supplies; `show_episode_files`: the coded files' episodes from `episode_files`, each listed once, from the first selected file in provider order that carries it, plus the code-less files `codeless_episode_files` maps, so a pack holding an episode twice is slotted on the file `observe` probed) + `quality`, writes `selection` entries (a series pack takes a sibling-episode slot held by another owned release only when `selection::takes_slot_from` allows it: the served rank of each copy's file (resolution, then source tier, then checked before unchecked, an untagged axis the lowest) must be higher, a checked copy giving way to an unchecked one only for a higher resolution, and at equal rank the score decides; with no quality on either side the slot is kept.
This matches the selection repoint, so that pass never moves the slot back); on fail — `fail_and_reacquire` deletes the hash under every listing id of it (`observe`'s `ids_by_hash`).
Only once every delete has succeeded does it blacklist the hash, drop its records (`Store::forget_owned`) and re-scrape for the next candidate.
A failed delete keeps the records, unblacklisted, along with the state that triggered the rejection (stall timer, info-failure timer, probe back-off, WrongTitle strike), so the delete is retried on the next tick (`ProbeUnfetchable` on its next back-off re-probe).
The kept owned record stops the mirror re-adopting the hash.
The blacklist is written only after the delete because a kept Pending record may still settle `Verified`, and for an empty-provenance one a non-"Dead" entry would let the phantom reaper drop that present copy.
`observe` returns the hashes whose listed torrents it deleted.
Before re-acquiring from a stored request that has no TMDB languages (`spoken_languages == None`: an account-mirror record the upgrade pass has not backfilled yet) under `AUDIO_LANGUAGE=original`, it looks them up (`fill_missing_languages` → `TitleValidator::title_languages`; `TmdbTitleValidator` calls TMDB `details`).
Ranking then resolves the audio requirement, and the replacement's record carries the languages.
Acquisition still accepts a release whose tracks can't be checked (`VerifyResult::Accept`: `Unsupported`/`TracksNotFound` container, e.g. `.avi`, or no tracks) when nothing better was found, but `record_verified` stamps its `quality.unverified = true` (a `Pass` stamps `false`, unless it checked no audio language: `AUDIO_LANGUAGE=original` with no TMDB languages known, `AcquisitionEngine::audio_unchecked`, the case of a failed language lookup on a dead-reap re-acquire) so the upgrade pass later replaces it with a checked copy.
It settles the record through the atomic `Store::mark_verified_if_present` and writes no `selection` for a record removed while its probe ran.
Reaps genuinely-dead torrents after `ACQUIRE_DEAD_TIMEOUT_SECS` (default 600s).
Stall detection (`STALL_TIMEOUT_SECS`) is preserved.
A probe that keeps coming back **`Transient`** (CDN momentarily unavailable) is re-probed every tick for the first `MAX_VERIFY_ATTEMPTS`, then on a `VERIFY_BACKOFF` (1h) cadence — it is **never accepted unverified** (so a wrong-language release can't freeze into the library); it is treated as effectively broken and replaced (blacklist + re-acquire) only by a re-probe that still defers once it is past `VERIFY_DEADLINE_SECS` (24h, anchored on the persisted `added_at`) and has itself been deferring for at least `VERIFY_DEADLINE_MIN_DEFER` (2 h; in memory, so a restart starts it over).
So a download that took longer than a day gets at least one back-off re-probe after the fast burst, and a release is never replaced without a fresh failed probe.
A Transient probe also drops the provider's cached CDN URL (`invalidate`).
