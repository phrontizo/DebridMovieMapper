# `release.rs`

`RawCandidate` → `ReleaseInfo` parser (resolution, codec, HDR, size (Torrentio's `💾` size first, else the first bare `<n> MB/GB/TB` token not glued to a preceding word or number nor to a following letter or digit (`DD5.1.TBS` is no 1 TB release; `_`, `.`, `-` and spaces end it on both sides, so `Movie_2020_4.7GB_x264` reads 4.7 GB), never a `TB+` cached marker), seeders, cached flag, source tier).
`parse` reads its `\b`-bounded tags (resolution, cam and source tags, language words, `multi`) from the text with `_` mapped to `.` (the regex crate's `\b` counts `_` as a word character), so `Movie_2019_2160p_UHD_BluRay_x265` reads as 2160p BluRay; the size, seeders and cached marker read the original text.
`score`/`rank` with quality prefs; hard-filters the resolution ceiling, cam/telesync/screener sources, **and uncached zero-seeder releases** (quality/availability floor), where the bare cam markers (`cam`/`tc`/`scr`/`screener`/`r5`/`ts`) and the bare `WEB` source token count only in a line's tag part (after its first year, SxxEyy or `Season N` token, or the whole line when it has none; the bare `WEB` token also counts only when the text names no other source (`hdtv`/`pdtv`/`sdtv`/`tvrip`/`dvdrip`, `NON_WEB_SOURCE_TAGS`), since a show line's tag part and a pack's file line hold the episode title, so `S01E05.Web.of.Lies.720p.HDTV` stays HDTV; for the bare cam markers on a show line, i.e. one with an episode code, only from the first resolution/source/codec tag after the code, or, when no such tag follows (a pack's file line such as `S02E03 - Hidden Cam.mkv`), only in the token right after the code and only when it is the line's last token bar a container extension (`S01E01.CAM`, `S01E01.CAM.mkv`, but not `S01E05 - Cam Girl.mkv`), so an episode title such as `S02E03.Nanny.Cam.720p` isn't cam-rejected) or inside a bracket group, so a title word (`Cam (2018)`, `Body Cam`, an episode titled `Hidden Cam`, `Charlotte's Web`) doesn't cam-reject every release or make an HDTV release WEB; the unambiguous tags (`HDCAM`, `CAMRip`, `HDTS`, `TELESYNC`, `TELECINE`, `DVDScr`, `WORKPRINT`, …) count anywhere.
HDR is a substring test with `HDRip`/`HDRezka` excluded.
It then ranks by **resolution within the ceiling** (dominant), then source tier (REMUX>BluRay>WEB>HDTV), then bitrate.
`rank` sorts on `score`'s coarse terms first (`coarse_score`: cached, resolution, the wrong-language penalty), then puts a tagged source before an untagged one (`Source::Other`), then the full score (`rank_key`, which the upgrade engine's pack ranker uses too).
At the same cached state, resolution and language state an untagged release (recorded at source tier 0, which the upgrade pass treats as unknown quality and replaces) therefore never outranks a tagged one on its HEVC or bitrate bonuses.
**Audio-language tagging** (feeds `score`'s soft wrong-`AUDIO_LANGUAGE` penalty — applied when a release's tags match none of a concrete `Lang`/`AnyOf` requirement, never for a raw `Original`; never an exclusion — the probe is the real gate): separator-bounded full language names **and** 3+-letter scene abbreviations (`eng`/`rus`/`ita`/`ger`/`deu`, the French `fre`/`fra`/`vff`/`vfq`/`vfi`/`truefrench`, `spa`/`esp`/`castellano`/`latino`, `por`/`dublado`, `pol`, `jpn`, `kor`, `hin`, `ukr`, …) in `LANG_WORDS`, plus Torrentio's regional-indicator **flag emoji** (🇷🇺→`rus`, 🇬🇧/🇺🇸→`eng`, 🇮🇳→any of `hin`/`tam`/`tel`/`mal`/`kan` (Torrentio uses it for Hindi, Tamil and Telugu), … via `flag_languages`/`FLAG_LANGS`, ISO 639-2/B).
Never 2-letter tokens (they collide with ordinary words) and never subtitle-only markers (`vostfr`, `napisy`, `subs`).
A language word **adjacent to a whole subtitle-marker token** (`sub`/`subs`/`subbed`/`subtitle(s)`/`hardsub`/`softsub`) is a subtitle language and is not tagged: suffix form `[ENG SUB]`/`Eng.Subs`, prefix form `SUB.ITA`/`Subtitles: English` (and the run it starts, `Sub.ITA.ENG`) — unless the marker introduces the next language word (`iTA-ENG.Sub.ITA`: ENG stays audio).
So a subtitle tag neither invents a penalty (Japanese title + `[ENG SUB]`) nor cancels one (`KOREAN…ENG.SUB`).
The predicate, `wrong_audio_language`, compares with `probe::lang_eq` and never applies when a wanted language is "no language" (TMDB `xx`).
A separator-bounded `multi` tags the `mul` multi-audio wildcard **except** when directly followed by such a marker (Torrentio's `Multi Subs` = several subtitle languages); a word merely starting with `sub` doesn't count, so `MULTi.SUBFRENCH` still tags `mul`.
Known limitation: a title containing a language word (`The Italian Job`, `The Danish Girl`) tags it on every release of that title.
A flag can name a subtitle language (a VOSTFR release shows 🇫🇷), so a mis-tagged release takes a ranking hit but stays acquirable.
`is_target_improvement` (+ the `Improvement` enum: `None`/`Upgrade`/`Downgrade`) follows the same `score` ordering (strict score gain + a category jump: a higher resolution, or a higher source tier at the SAME resolution — never a same-resolution tier drop, even one that out-scores the owned copy on the HEVC/bitrate bonuses, since consolidation's tier+resolution gate could then fold such singles back into the lower-tier pack (a2) split them from, every visit) so upgrades stay consistent with acquisition and never flip-flop — except that an **`unverified`** cached owned copy is also improved by any cached candidate at `effective_score >=` and `resolution >=` (no category jump needed; converges because the upgrade pass adopts only a probe `Pass`, so the replacement is verified) — and, via the ceiling-aware `effective_score` (heavily penalises an owned copy's score once its resolution exceeds `MAX_RESOLUTION`, so a within-ceiling cached candidate always outscores it), also recognises a **corrective downgrade** when an owned copy sits above a since-lowered ceiling.
An over-ceiling current is corrected by a within-ceiling candidate with a tagged resolution even when its source is untagged; `upgrade::rank_changes` orders tagged sources first, so such a release is adopted only when no tagged one at its resolution qualifies.
**Unknown quality** (`is_unknown_quality`: a resolution or source tier of 0 — untagged — or no recorded quality at all, `QualitySummary::unknown()`) ranks lowest wherever qualities are compared, but a **known resolution stays a floor**: `quality_rank` orders copies by resolution, then source tier, then checked before `unverified` (an untagged axis is 0; score excluded — same rank = same quality; used by dedup and, through `selection::served_rank` / `takes_slot_from`, by the selection repoint and `observe`'s pack slot gate), and within the ceiling `is_target_improvement` rates any known cached candidate at or above the current's tagged resolution an `Upgrade` over an unknown current (never a lower resolution — that would be an ungated downgrade) and never an unknown candidate over anything.
A copy whose resolution is **above** the ceiling is never unknown (whatever its tier).
`QualitySummary::of_owned` snapshots an owned file's quality bypassing `score`'s hard filters (an over-ceiling file keeps its resolution, scored as if uncapped)
