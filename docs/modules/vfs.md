# `vfs.rs`

In-memory virtual filesystem: creates `Movies/`+`Shows/` hierarchy with media files and NFO metadata.
`build` consults the injected `SelectionMap` (slot → `{hash, file_path}`) to pick the representative file per title/episode; a slot with no managed selection (or a stale one) behaves as before SP3, so external/un-managed torrents are unaffected: a movie falls back to its largest streamable torrent, and an unmanaged show episode keeps every distinct file name, same-named copies resolving to the largest torrent.
Episode files are served under canonical names by default (`EPISODE_FILE_NAMES`, `EpisodeNames`; the scan loop calls `build_with`, while `build` serves original names for the tests and the live test binaries): `canonical_episode_name` builds `<title> (<year>) - S01E02.<ext>`, or `S01E01-E02` for a contiguous multi-episode file, from the episodes the build places the file under (its `parse_se_all` codes, else the episode `codeless_episode_files` maps it to in the season folder it lands in), leaving out a year that isn't four digits and a title holding an episode code of its own.
A file it can't number, or whose codes span seasons or aren't contiguous, keeps its own name.
Copies of an episode share the name (the build compares names without the extension), so a season folder shows one (`ShownCopy::beats`): the slot's file, else a coded file before a code-less one mapped to the episode, then the better resolution and source tier the file's name or nearest folder tags (`tagged_quality`), then the larger file.
Under original names the slot's file still wins a collision of identical names, and otherwise the larger torrent's copy stays.
The build knows no title language, so a pack holding an episode in two languages with no slot for it shows the better-tagged or larger file rather than both; once two owned copies hold the episode, the selection pass's slot, which applies the wrong-language test, decides.
Kodi's default `tvshowmatching` rules read further codes out of an episode title (`S00E41 - Inside the Episode S2 E1` also as S02E01, `S03E03.4-5-1` as E03, E05 and E01), so a name with only its code before the extension leaves Kodi nothing to misread; the test-only `kodi_episodes` ports those rules and `kodi_reads_every_canonical_name_as_its_episodes` pins the form.
A multi-episode file (`S01E01E02`, Sonarr's `S01E01-02`, where a dash-only continuation counts only when it names the next episode and isn't a channel layout such as `S01E04-5.1`, or its "Duplicate" style `S01E01.S01E02` / `S01E01 - S01E02`, where a separated code of another season ends the run) is hidden only when every episode it carries is selected from another present copy, so a slot that selects it for a later episode keeps it visible.
A file name with no episode code takes its season from an `Sxx`/`Season N`/`NxNN` token in the file name, else from the nearest directory that names one, so a multi-season pack's root folder (`Show.S01-S03/Season 2/01.mkv`) doesn't put every season in its first one, else from a `Part N` in the file name (usually a two-part episode title, so any directory season beats it).
The `Sxx`, `NxNN` and `Part N` tokens need a non-alphanumeric character, or the start or end of the name, on each side (an `Sxx` may also run on into an `E`), and `_` counts as one (`Show_S02_1080p/01.mkv` and `Show_Part_2/01.mkv` land in Season 02).
An `NxNN` token whose season digit follows `<digit>.` and whose digits after the `x` are `264` or `265` is a channel layout run into a codec (`AAC2.0x264`, `DD5.1x264`, `is_channel_layout_codec`) and names no season, as `parse_se_all` reads it, so the directory's season places the file.
`season_tokens` is `pub(crate)`: `upgrade::is_pack_stream` uses it to recognise a season pack's torrent name.
`explicit_season_of_codeless_file` reads a code-less file's season the way `season_of_codeless_file` places it (they share `nearest_codeless_season`), but names none for the season-1 default, a file-name `Part N`, or a nearest name that names a season range (`[Group] Show (Season 1-2)`, `Show.S01-S03`, `Season 1&2`, `Season 1+2`, `Seasons 1-3`, and in a directory a glued `Show.S01-03` / `Show S1-3` whose second number is the greater: `season_range`).
A directory that names only a range (`Show Seasons 2-3/`) places a code-less file in the range's first season, and an aspect ratio (`16x9`) beside a season token is no second season.
`codeless_episode_files` maps a code-less file of a multi-file pack only under such an explicit season (or, for a part of a total such as `2of4`, in season 1 when nothing names a season and the pack's parts are one run), and the `vfs` test `explicit_codeless_season_agrees_with_the_vfs_placement` pins the explicit season to the one `season_of_codeless_file` places the file in.
`part` takes a 1-2 digit number, so `Counterpart.2017` is no season 2017.
A `Part N` directory still names the season and, as the nearest one, beats an outer `S04` (`Show.S04/Part 2/01.mkv` → Season 02).
A group whose torrents share a TMDB id but carry different titles takes its folder and NFO name from the smallest (title, year), so the listing order cannot rename the folder.
`parse_se_all` (every episode code in a file name: `SxxEyy`, also with one `.`, space or `_` before the `E` (`S01.E05`); `NxM` (`2x05`, with a 1-2 digit season and a 2-3 digit episode, never `00`, bounded by a non-alphanumeric character or the string edge, so `1920x1080`, `16x9`, `x264` and `DD5.1x264` are not codes; only a channel layout run into `x264`/`x265` is skipped, so a code after a year or a title ending in a digit, such as `Show.Name.2005.1x01` or `Babylon.5.2x10`, is read, and `season_tokens` applies the same test to an `NxNN` season token); their multi-episode forms (`S01E01E02`, `S01E01-02`, `S01E01.S01E02`, `S01E01 - S01E02`, `1x01x02`, `1x01-1x02`); an `NxM` code with a version suffix (`1x01v2`), read the way `S01E01v2` is; and the dash-concatenated `Show - 409 - Title`) lives here and is the only copy: the acquisition engine calls it for `provides`, the selection slots `observe` writes and the title check, so for a coded file the VFS and the engine agree on which file supplies which episode.
The episode readers built on it live here too: `episode_files` (episode codes only; the account mirror and `tasks::backfill_owned_provides`), `codeless_episode` and `codeless_episode_files` (a file with no code that names its episode by `EPISODE_WORD_RE` or a trailing ` - NN` number) and `show_episode_files` (both, in file order; `observe` and the upgrade engine's staging sites).
The VFS calls nothing in `acquire`, and `acquire`, `tasks` and `upgrade` call these through `vfs`.
`locator_for_selected` and `selected_locators` (the FileLocators of a torrent's selected files, Real-Debrid links paired by position) live here as well, for the instant repair and `acquire::locator_for`.
A file with no episode code is placed by season only (`season_of_codeless_file`), while the engine may map it to the episode its name gives (`codeless_episode_files`) and slot it there.
The selection gate hides such a file by that same mapping when another present copy's slot serves its episode, so a moved slot doesn't list the episode twice.
`selected_files_with_links` is the one copy of Real-Debrid's positional link pairing among selected files: the build (`emittable_video_files_with_links`), `repair`'s replacement locator and `acquire::locator_for` / `locator_for_selected` read it.
An `NxM` or separated code followed by a range past the next episode (`1x01-10`, `S01.E01-10`) decodes to nothing, so `upgrade::is_single_episode_stream` never reads such a pack name as a single episode.
`is_video_file` maps `_` to `.` before its keyword and year checks (the regex crate's `\b` treats `_` as a word character, so `show_s01e01_720p_sample.mkv` used to pass as an episode), and treats a `sample` keyword anywhere in the name, and any file under a `Sample/`/`Samples/` folder, as an ancillary clip even when it carries an episode code.
An episode code (any `SxxEyy`, `NxM` or dash-concatenated `Show - 105 - Title` form `parse_se_all` reads) still keeps a real episode whose title has another keyword before the code, or that is mis-foldered under an extras/bonus directory.
A `trailer`/`extra(s)`/`bonus`/`featurette` word after the code is part of the episode title (`Show.S03E07.The.Extra.1080p`, `Show - S02E05 - Bonus Round`, `Show - 105 - The Extra Mile`) unless it is the first word after the code and only the end of the name, a release tag or a trailing `-GROUP` follows it (`Show.S01E05.Featurette`, `Show.S01E05-trailer`, `Show.S01E05.Extras.1080p`), or it sits after the first release tag (`Show.S01E01.1080p.WEB-GRP.featurette`); those are still extras clips.
So an episode titled with the bare keyword (`S01E05.Extras.1080p`) is still excluded, and `S01E05.Featurette.Making.Of` is kept.
The archive-only and selected-file/link-count warnings fire once per torrent per process, then at debug.
