# Acquisition and upgrades

## SP1 Acquisition Engine (historical)

**SP1 Acquisition Engine (historical — superseded by the SP3 optimistic-add model below; `acquire` no longer materialises/validates/probes synchronously, it adds the best candidate and defers the verdict to `observe`):** When a title is requested (by the SP2 Trakt reconciler — `reconcile_wanted`/`monitor_episodes` — which replaced the temporary `--acquire` CLI), the engine originally ran: (1) **Scrape** — `TorrentioScraper` calls a Stremio-compatible addon (default: Torrentio, URL auto-templated from `<provider>=<token>`; override with `SCRAPER_ADDON_URL`).
(2) **Score/rank** — `release::parse` extracts resolution, codec, HDR, size, seeders, cached flag, and source tier; `release::rank` hard-filters the resolution ceiling (`MAX_RESOLUTION`), cam/telesync/screener sources, **and uncached zero-seeder (undownloadable) releases** (so the engine never burns acquire attempts on dead torrents or leaves "checking" magnets behind), then sorts by a weighted score: cached availability dominates, then **resolution within the `MAX_RESOLUTION` ceiling** (a user who raises the ceiling to 2160p wants 4K, so resolution outweighs source tier), then source tier [REMUX>BluRay>WEB>HDTV], then progressively smaller **additive** bonuses — HEVC (+5k), HDR (+3k), verifiable container (+2k), bitrate (up to +3k), seeders (up to +2k) — which **combine into the weighted sum rather than forming a strict tie-break chain** (e.g. the HEVC bonus can outweigh a one-step source-tier difference, and bitrate can outweigh the container bonus; `rank` orders by cached, resolution and the language penalty first, then tagged source before untagged, then that sum, so the HEVC bonus never lifts a release with no source tag above a tagged one at the same resolution), with a configured-`AUDIO_LANGUAGE` mismatch applied as a large penalty; see `release::score` for exact magnitudes.
(The default `AUDIO_LANGUAGE=original` is resolved per-title via `QualityPrefs::with_resolved_audio(original_language, spoken_languages)` **before** ranking — to `Lang(x)` when the title's TMDB original ∪ spoken languages (`config::original_audio_languages`: de-duplicated, original first) is one language, `AudioReq::AnyOf(..)` when several (never produced by parsing the env var), unchanged `Original` when none is known — exactly how `probe::verify` resolves `Original` — so a wrong-language release is down-ranked up front rather than ranking #1, getting optimistically added, and only then being rejected at probe time; a release in a spoken language (e.g. a `fi`-original film whose dialogue is mostly English) is not penalised.
Accepted trade-off: a dub in a secondary spoken language is accepted too.)
(3) **Materialise** — re-adds the torrent by hash, waits for the file list, and selects the target file; **a movie request whose materialised torrent has more than one feature-sized video is rejected as a multi-movie pack** (providers like TorBox auto-select all files).
(Post-SP3 only `repair.rs` calls `reacquire::materialise`; `acquire`/`observe` add optimistically.)
A candidate whose materialise *fails* (provider "already queued", or an add whose file list never resolves) has any leaked torrent for its hash deleted before the next candidate is tried, so a rejected/failed candidate never lingers as a dead "checking" torrent.
(4) **STRICT title validation** — `TmdbTitleValidator` runs `identify_name` on the selected file's name and verifies the result resolves to the requested TMDB id; mismatches are blacklisted and the next candidate is tried.
(5) **File-probe** — `HttpProber` fetches the first 4 MB of the CDN URL and uses the hand-rolled `probe::probe_tracks` (MKV/MP4) to extract audio/subtitle language codes; corrupt probes are blacklisted, wrong-language probes are blacklisted, unknown formats are accepted unless the release's own name tags only a wrong audio language (`AcquisitionEngine::named_wrong_audio`), in which case it is blacklisted as `BadAudio`.
(6) **Outcome** — `Acquired` (cached + verified), `Pending` (downloading or probe deferred), `NoAcceptableRelease`, or `TemporarilyUnavailable`.
`observe` monitors Pending torrents each scan tick: stall detection (no progress for `STALL_TIMEOUT_SECS`), deferred probe retry (up to `MAX_VERIFY_ATTEMPTS`), and fail-and-reacquire.
The `authoritative_ids` table overrides filename identification for engine-owned torrents; the `blacklist` table prevents re-adding rejected hashes.

## SP3 — Optimistic-add + asynchronous reconcile (always-on robustness + daily quality)

`acquire` now **adds the best candidate optimistically** and records it `Pending` — no synchronous 15s poll, pack-guard, title-validation, or probe.
`observe` (every scan tick, no scraping) is the resolver: once files appear, the deferred gates run; on pass it marks `Verified`, records `provides` (which `(season, episode)` pairs the hash supplies) and a `quality` summary, and writes `selection` entries; on fail it blacklists the hash and re-scrapes for the next-best candidate.
Genuinely-dead torrents (provider error status, or no resolution after `ACQUIRE_DEAD_TIMEOUT_SECS`) are reaped and re-scraped.

**Selection inversion:** "which release represents this title/episode" is a persisted `selection` table (slot → `{hash, file_path}`) that `vfs::build` consults on every scan; a slot with no managed selection keeps the pre-SP3 behaviour (a movie's largest streamable torrent; every distinct file name of an unmanaged show episode, which under canonical episode names is one file per episode).

**`provides` kills season-pack churn:** the union of `provides` across a show's owned hashes is the owned-episode set — a season pack reports all its episodes as owned so `monitor_episodes` never re-acquires them.
**Daily upgrade engine** (`upgrade.rs`, on by default, disable with `UPGRADE_INTERVAL_SECS=0`): re-scores every eligible owned title each pass (see `docs/modules/upgrade.md`; copies of unknown or unchecked quality first; `UPGRADE_BUDGET_PER_TICK` caps it) and stages a meaningfully-better CACHED release (`is_target_improvement`: uncached→cached, or a strict `score` gain on a category jump — a higher resolution, or a higher source tier at the same resolution: never trading resolution for tier, nor tier for a bonus — that still holds with the candidate scored under the title's resolved audio as acquisition ranks it, so a wrong-language-tagged release acquisition would rank below the owned copy is never adopted — or, for an owned copy flagged `unverified` (its tracks couldn't be checked), any equal-or-better cached release at the same-or-higher resolution — or, for an owned copy of **unknown quality** (none recorded, or an untagged resolution/source tier: the lowest quality), any known-quality cached within-ceiling release at or above its tagged resolution; an unknown candidate never improves a cached copy within the ceiling (an untagged-source one may still correct an over-ceiling copy), and an over-ceiling copy is never unknown); staging adopts only a probe `Pass`, so an upgrade never swaps a checked copy for an unchecked one; idle-gated swap (`UPGRADE_IDLE_SECS`) + prune of the superseded torrent ensure an active stream is never interrupted.
The staged replacement inherits the provenance of the copies it supersedes (`upgrade::superseded_provenance`), and gets an empty one as soon as one of them is a mirror record, so an upgraded mirror copy stays a mirror record.

**Shows now get the same quality-upgrade treatment as movies, at per-episode granularity:** every owned singleton episode is independently re-scored and swapped, run BEFORE that season's pack/consolidation handling so a freshly-upgraded episode can still be folded into a pack later the same tick.
**Episodes served from a within-ceiling multi-episode pack** are then re-scored against the pack's quality and moved to a better cached true singleton at the same-or-better source tier and resolution (consolidation's no-regression test; since no upgrade lowers a single's tier at the same resolution, consolidation never folds the split pack back — bar one re-fold of an unverified pack split into equal-quality singles) the same way; the pack is pruned only once it serves no slot and every episode it provides is held by another `Verified` owned record that is still present on the provider (otherwise kept), with a sample-first bound (a first served episode with no improving candidate, or whose only improving candidates turn out to be season packs, skips the rest of that pack this visit).

**Corrective downgrade (opt-in):** when `MAX_RESOLUTION` is lowered below an already-owned copy's resolution, `effective_score` penalises that copy so a within-ceiling CACHED candidate now reads as an improvement (`Improvement::Downgrade`); this only executes swap+prune when `ALLOW_RESOLUTION_DOWNGRADE=true`, applies to both a movie/episode singleton AND an over-ceiling season pack (`correct_over_ceiling_packs`, same same-episode-coverage + idle-gated-swap discipline as consolidation), and is a no-op — logged as a preview (`upgrade: … would downgrade …`) — when unset (the default) or when no conforming cached replacement exists (a sole over-ceiling copy is kept, never deleted with nothing to replace it).

**Full-season consolidation (unchanged, layered after the per-episode passes):** the same engine finds a CACHED full-season pack covering all aired episodes at same-or-better quality and consolidates scattered per-episode torrents into it, idle-gated; consolidation itself never regresses quality and is not part of the downgrade path.
No show swap deletes a copy holding a video file with no episode code that its record doesn't account for (an OVA, an anime absolute number in a mirrored pack), since `provides` leaves that file out and no other copy holds it: the slot moves and the old copy stays.

## `--acquire` CLI removed

The temporary SP1 verification CLI was deleted in SP2; Trakt sync + the reconciler are the acquisition triggers now.
A `scheduler.rs` source-guard test (`acquire_cli_is_removed`) fails if the flag is reintroduced into `main.rs`.
