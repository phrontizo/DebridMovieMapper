# Account mirror

## Account mirror = owned (no protected "manual" class)

The scan loop's `record_mirror_owned` records every identified, present provider torrent the engine doesn't already track (except a hash the engine has blacklisted for ANY title, hash-wide via `all_blacklisted_hashes`, a hash with an open staging intent (an upgrade candidate or an acquisition being added, or cut off mid-add), and a torrent whose cached info lists no emittable video file (a lapsed TorBox entry, one listed with `files: null`, an archive-only torrent), which is adopted once its files are back; none of these is ever mirrored.
An existing `Verified` mirror record is reaped as a phantom, store-only, with its authoritative id + selection slots, only when it is no newer than its hash's newest non-"Dead" blacklist entry: see `docs/modules/tasks.md`) as a **`Verified` owned record with EMPTY provenance** (a show's `provides` = the SE-parsed set of its selected video files; a movie's is empty; `quality` is **derived from the representative/largest video file**, with any axis its name leaves untagged filled from the torrent name (`mirror_quality` → `QualitySummary::of_owned`) — `cached: true` since it is present — so the record is comparable on the dedup/upgrade/consolidation paths: an axis neither name tags is recorded as 0 (**unknown — the lowest quality** at its resolution, so a known cached release at or above that resolution that passes the probe may replace it), a file **above the resolution ceiling keeps its real resolution** (never unknown-lowest; replacing it is a gated corrective downgrade), and a torrent with no video file (a lapsed TorBox entry lists none) is not mirrored at all until its files are back.
Older mirror records stored `None` for the first two cases; `backfill_owned_quality` re-derives their quality from their file names (scan loop + every upgrade tick): a still-`None` record, or a mirror record whose untagged resolution or source tier its file names now tag (`Store::replace_quality_if_eq`, a compare-and-set).
An older record of a torrent that lists no video file (no quality, no `provides`) is dropped by the mirror pass instead.
A recorded quality is flagged `unverified` iff the representative file isn't `.mkv`/`.mp4` (a mirrored MKV/MP4 was never probed either but is assumed fine — flagging it would churn the whole library) — set when the mirror record (or a backfilled quality) is created, so it covers mirror copies recorded from schema v8 on; a pre-existing mirror copy that already had a quality is **not** flagged retroactively (it has no `selection` entry for the v8 migration to find, and `record_mirror_owned` only fills a missing quality or heals an axis it left untagged, never otherwise rewrites one); `imdb_id` resolved from TMDB `external_ids`, cached per-title, best-effort; an id lost to a transient failure is filled by the daily `backfill_missing_imdb_ids`).
This makes the reconciler/episode-monitor aware of the user's **pre-existing library**, so a watchlisted/in-progress title that is already present is **not re-acquired as a duplicate**, and a pre-existing season pack reports its episodes as owned (no per-episode `monitor_episodes` churn).
Empty provenance means the record is owned **exactly like an engine-acquired title** — eligible for the daily quality-upgrade / consolidation path (the replacement of an upgraded mirror copy stays a mirror record: empty provenance; deliberately NOT a `Manual` protected class, so manually-added content follows the same upgrade path) — while still being **kept** under the normal lifecycle: with no Trakt wanter and no watchlist provenance, neither removal trigger (`trigger_a_finished`/`trigger_b_abandoned`) fires for a mirror-only group, and Trigger **B** (abandoned watchlist) never deletes a mirror hash even when it shares a `tmdb_id` with watchlist-acquired episodes (removal is scoped to the group's engine-acquired hashes — `OwnedGroup.engine_hashes` — via `removal_hashes`).
It is idempotent and non-destructive — an engine-owned or already-mirrored hash is never clobbered.
It trusts the identification: a torrent matched to the wrong title is mirrored under that title's TMDB and IMDB ids, so the upgrade engine replaces and prunes it as that title (`supersede_hashes` never looks at what a copy holds) and dedup groups it with real copies, and nothing re-identifies a cached match.
README warns operators to check a new deployment's library with `UPGRADE_INTERVAL_SECS=0` first.
A real guard needs a stored identification confidence or a per-title override; re-running `validate_title` on the owned file name would only repeat the wrong match.
`observe`'s dead-torrent re-acquire skips only records with **no IMDB id** (can't re-scrape → leave for on-read repair), not by provenance.
**A mirror hash (empty provenance) is protected from the general Trakt removal lifecycle**, even when a Trakt user *wants* the title (it shares the `tmdb_id`): a removal must never delete content the engine didn't acquire (the sync no longer writes a title still in `/sync/playback` as finished, so for a paused re-watch this guard is a backstop).
`removal_hashes` enforces this — for a `Finished` (Trigger A) removal it returns only the group's **engine-acquired** hashes (`OwnedGroup.engine_hashes`) EXCEPT in the one opt-in case: a **show** with `REMOVE_FINISHED_SHOWS=true`, where the finish-cleanup *folds* fully-watched ended owned shows into the wanted-set specifically to reclaim the full set (incl. pre-existing library copies).
Trigger **B** (abandoned watchlist) also returns only engine hashes.
So a mirror torrent is removed only by (a) the explicit duplicate-dedup pass (where it gets **no** protection — it competes on quality like any engine copy) or the upgrade engine superseding it with a better release, (b) `REMOVE_FINISHED_SHOWS=true` show finish-cleanup, (c) when it is *also* engine-acquired (mixed group) and that engine hash is reclaimed, or (d) `observe`'s dead-status reap (`fail_and_reacquire`, Real-Debrid statuses only, not idle-gated since the torrent can't be streamed; a movie is replaced, a mirror show record is not).
A pure-mirror **movie** is never finish-removed (movies are never folded).
`reconcile_title`'s symmetric acquire-side guard (both the Movie and Show branches short-circuit on `trigger_a_finished`, except for manual content) means an engine-reclaimed title is **not** re-acquired the next tick — no acquire↔remove flip-flop; to keep a watched title available, watchlist it.
