# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Project Does

DebridMovieMapper is a Rust async service that bridges a debrid service — **Real-Debrid or TorBox** — with media servers like Jellyfin and Plex. It fetches torrents from the configured debrid account, identifies them via TMDB metadata, and exposes a WebDAV endpoint serving proxied media files (the actual `.mkv`/`.mp4` bytes are fetched from the provider's CDN on demand). Exactly one provider is active per deployment, selected at startup by which token is set (`RD_API_TOKEN` or `TORBOX_API_KEY`).

Optionally, the library can be **driven by users' Trakt accounts** (SP2): when Trakt sync is configured, each enrolled user's watchlist and in-progress titles auto-acquire content and a reconciler lifecycle-removes it once everyone who wanted it has finished (or abandoned) it — alongside the existing manual/account-mirror behaviour, which is unchanged when Trakt is not configured.

- A debrid provider token — exactly one of:
  - `RD_API_TOKEN` — Real-Debrid API token
  - `TORBOX_API_KEY` — TorBox API token

  Set one or the other, not both. Setting **both** is a startup error; setting **neither** is a startup error.
- `TMDB_API_KEY` — TMDB API key

**Optional:**
- `SCAN_INTERVAL_SECS` (default: 60, minimum: 10) — how often to poll the active debrid provider
- `DB_PATH` (default: `metadata.db`) — path to the redb database file
- `PORT` (default: 8080) — WebDAV server listen port
- `RUST_LOG` (default: `info`) — log verbosity via a `tracing-subscriber` `EnvFilter` directive (the `env-filter` feature is enabled). Unset → `info` (unchanged behaviour); a malformed directive falls back to `info` rather than crashing startup. Scope it to this crate to avoid dependency noise, e.g. `RUST_LOG=debridmoviemapper=debug`, or target one module: `RUST_LOG=debridmoviemapper::acquire=debug,info`. Takes effect on (re)start. The acquisition lifecycle is instrumented for `debug`: `acquire` (scrape count, ranked top-3 with cached/resolution/source/seeders, the candidate added, idempotent/lapsed/NoAcceptableRelease outcomes), `observe` (per-tick reason a Pending torrent is still waiting — absent/no-files/selecting/downloading/probe-deferring — plus reaps at `warn` and `Verified` at `info`), `scraper` (candidate counts; never the token-bearing URL), `tasks` (Trakt wanted-set sizes, reconcile op counts), and `dav_fs` (playback resolves; never the CDN URL).
- `JELLYFIN_URL` — Jellyfin server URL (e.g. `http://jellyfin:8096`)
- `JELLYFIN_API_KEY` — Jellyfin API key
- `JELLYFIN_RCLONE_MOUNT_PATH` — rclone mount path as seen by Jellyfin (e.g. `/media`)

**Optional — Acquisition quality preferences (SP1):** (full descriptions in `README.md`'s env-var table)
- `MAX_RESOLUTION` (default: `1080`) — hard resolution ceiling for acquisition (`720`/`1080`/`2160`); candidates above it are excluded.
- `AUDIO_LANGUAGE` (default: `original`) — required audio language: a 2-/3-letter ISO code or `original` (TMDB's original language).
- `SUBTITLE_LANGUAGE` (default: unset = `none`) — required subtitle language (ISO code), or `none`/unset to skip the check.
- `PREFER_HEVC` (default: `true`) / `PREFER_HDR` (default: `false`) — scoring preferences for HEVC and HDR/Dolby-Vision encodes.
- `STALL_TIMEOUT_SECS` (default: 1800, minimum: 60) — seconds without download progress before a Pending torrent is re-acquired.
- `MAX_ACQUIRE_ATTEMPTS` (default: 5, minimum: 1) — candidates tried before giving up on a title.
- `SCRAPER_ADDON_URL` (default: auto-templated from the provider token) — override the Torrentio/Stremio addon base URL.
- `SCRAPER_PROXY_URL` (default: unset) — route ONLY the scraper's traffic through an HTTP(S) proxy (a non-http(s) scheme is a startup error); CDN/TMDB/provider stay direct.

**Optional — Trakt sync (SP2):**
- `TRAKT_CLIENT_ID`, `TRAKT_CLIENT_SECRET` — both required to ENABLE Trakt sync (from a Trakt API app). If either is absent, Trakt sync is disabled and the service runs exactly as before (account-mirror + on-demand repair only).
- `TRAKT_SYNC_INTERVAL_SECS` (default: 900, minimum: 60) — Trakt sync + reconcile cadence.
- `TRAKT_EPISODE_CHECK_INTERVAL_SECS` (default: 3600, minimum: 300) — episode-monitor cadence. (Note this exact env var name — it carries the `TRAKT_` prefix for consistency.)
- `TRAKT_CATCHUP_LOOKBACK` (default: unset = all-time) — **catch-up** lookback window. A show you've *watched* (not just watchlisted/in-progress) is auto-acquired to catch up on episodes aired since you last watched it, but only if you last watched it within this window. Accepts `<N>d` / `<N>w` / `<N>mo` (e.g. `90d`, `12w`, `6mo`), a bare number = days, or `0`/unset = all-time (every watched show with unwatched aired episodes qualifies). Anchored on Trakt's per-show `last_watched_at`. A malformed value is treated as all-time (logged at warn), never a startup failure.

  Accounts are linked via the local-network enrolment page (`/trakt/accounts` on the WebDAV listener), not a static list.

**Optional — Upgrade engine (SP3):**
- `UPGRADE_INTERVAL_SECS` (default: 86400 = daily; `0` disables; minimum 600 when non-zero) — how often to run the quality-upgrade + full-season consolidation pass. On by default; set to `0` to disable entirely.
- `UPGRADE_BUDGET_PER_TICK` (default: 20, minimum: 1) — maximum number of owned titles re-scored per upgrade tick (round-robin across the library).
- `UPGRADE_IDLE_SECS` (default: 300, minimum: 30) — seconds of proxy read inactivity before a slot is considered idle enough to swap/prune.
- `UPGRADE_STAGE_MAX_SECS` (default: 604800, minimum: 3600) — reserved; maximum age of a staged upgrade before it is abandoned (informational for now).
- `ACQUIRE_DEAD_TIMEOUT_SECS` (default: 600, minimum: 120) — seconds an optimistically-added `Pending` torrent may remain unresolved before `observe` reaps it as dead, blacklists the hash, and re-scrapes.
- `DEDUP_REMOVE_DUPLICATES` (default: unset/`false`) — when `true`/`1`/`yes`/`on`, the duplicate-dedup pass actually **deletes** redundant torrents from the provider. Default is a **dry-run** that only logs the plan (`dedup: …` lines) so it can be reviewed first. Removal is additionally idle-gated (`UPGRADE_IDLE_SECS`) so it never interrupts an active stream.
- `REMOVE_FINISHED_SHOWS` (default: unset/`false`) — when `true`, a fully-watched **Ended** show that isn't watchlisted is auto-removed (Trigger-A finish cleanup), **including shows already in the library**. Default `false` only **logs** the finish-removal candidates (`trakt: <user> — N finished+ended owned show(s) would be removed (preview …)`) without removing — review the preview, then enable. (Mechanism: `sync_trakt` folds the finished+ended owned shows into the wanted-set only when this is on, so the reconciler's existing Trigger-A removal fires; the acquire path acquires nothing since every episode is watched. A watchlisted show is never finish-removed.)

## Architecture

The project is structured as both a binary (`main.rs`) and a library (`mapper.rs` as lib root).

**Background tasks (the scheduler model, SP2):** `main.rs` spawns `scheduler::run`, which spins up cooperating independent periodic jobs over the shared `AppState` (each driven by the `scheduler::periodic` primitive — run immediately, then every interval, until shutdown):
- **Scan loop** = `run_scan_loop` (every `SCAN_INTERVAL_SECS`, behaviour-preserving): two conceptual sub-steps (NOT separate functions — both inlined in `run_scan_loop`) sharing one `get_torrents` per tick — the *account sync* (poll the active debrid provider → identify torrents via TMDB → `update_vfs` + `record_mirror_owned` + `dedup_owned`) **plus** *acquisition verification* (`engine.observe`). Implemented in `tasks.rs`.
- **Trakt cycle** = `sync_trakt` then `reconcile_wanted` (sequentially, so the reconciler sees the just-synced wanted set), every `TRAKT_SYNC_INTERVAL_SECS`. Spawned **only** when Trakt is configured.
- **Episode monitor** = `monitor_episodes` (every `TRAKT_EPISODE_CHECK_INTERVAL_SECS`). Spawned only when Trakt is configured.
- **Upgrade job** = `run_upgrade_once` (every `UPGRADE_INTERVAL_SECS`, default 86400s/daily; gated on `UPGRADE_INTERVAL_SECS > 0`): re-scores owned titles, stages meaningfully-better CACHED releases, and performs an idle-gated swap of the `selection` + prune of the superseded torrent; also consolidates scattered per-episode torrents into full-season cached packs (no quality regression). Disable by setting `UPGRADE_INTERVAL_SECS=0`. Implemented in `upgrade.rs`.

The Trakt cycle + episode monitor are gated on `scheduler::trakt_jobs_enabled` (a Trakt client **and** `config.trakt` both present); otherwise only the scan loop runs and the service behaves exactly as before Trakt. The local-network Trakt enrolment routes (`/trakt/accounts`) are served on the existing WebDAV listener.

**On-demand (synchronous, during WebDAV file reads):**
- **Repair:** Triggered when a media file is read and `provider.resolve_url` returns `AppError::Unavailable` (RD maps any 5xx on unrestrict to it), **or** when the CDN returns a persistent **5xx** on the byte fetch (the file resolved but is broken on the provider, not just a stale URL — after the cheap fresh-URL retry still 5xxs, the byte-fetch path escalates to the same instant repair, once per read, bounded by the repair cooldown). For cached torrents, repair completes inline (~1-2s delay); for non-cached torrents, the file fails and a new torrent is left to download. A persistent 5xx is no longer an endless player retry-storm.

|------|---------|
| `main.rs` | Initializes shared state, spawns the scheduler (`scheduler::run`, which runs the scan loop + the Trakt/episode/upgrade jobs), starts the WebDAV server on port 8080. Connections are bounded by a `MAX_CONNECTIONS` (256) semaphore, and `http1::Builder` sets a `header_read_timeout` (60s) so an idle/dead keep-alive connection can't pin its permit indefinitely (a dead peer would otherwise leak permits until the pool exhausts and the service silently rejects all new connections). `--healthcheck` mode issues a real `OPTIONS /` HTTP request (not a bare TCP connect) so an exhausted-pool/wedged server reports UNHEALTHY rather than falsely healthy. |
| `config.rs` | `Config` — all startup env parsing/validation (`from_env`/`from_parts`); shaped for a future DB-override layer. Also parses the optional `TraktConfig` (`Some` only when both `TRAKT_CLIENT_ID` + `TRAKT_CLIENT_SECRET` are present; carries the two Trakt interval knobs plus the optional `catchup_lookback_secs` from `TRAKT_CATCHUP_LOOKBACK`) |
| `app_state.rs` | `AppState` — `Clone` bundle of shared handles (provider, tmdb, vfs, store, repair, config, jellyfin, http, scraper, engine, trakt_client, read_activity) carried by the scheduler's jobs |
| `tasks.rs` | `run_scan_loop` — polls the provider, identifies new torrents, updates VFS (+ `engine.observe`), and `record_mirror_owned` (the **account mirror**: every identified present torrent the engine doesn't already track is recorded as an owned record with empty provenance — owned + upgradeable, not a protected manual class — so the reconciler sees the user's pre-existing library: no duplicate re-acquire, and a season pack's episodes count as owned). Then `dedup_owned` (the **duplicate cleanup**: `plan_dedup` finds titles covered by more than one present owned hash and, per title, keeps one + marks the redundant ones for removal — a movie keeps the top-priority hash, a show keeps a greedy episode set-cover so complementary packs are all kept and only a fully-covered hash is removed; keep-priority = currently-served > higher `quality.score` > more episodes > hash. Also hosts the SP2 Trakt jobs: `sync_trakt` (materialise each user's `wanted` set), `reconcile_wanted` (movie acquire/re-acquire + show Trigger-B removal), and `monitor_episodes` (show episode acquisition + Trigger-A finish removal). The destructive `execute_remove` is **idle-gated** (`UPGRADE_IDLE_SECS`, like dedup/upgrade) so a Trigger-A/B removal never interrupts an active stream — important in a multi-user household; a deferred removal is left intact and retried on a later idle tick |
| `provider.rs` | `DebridProvider` trait abstracting the debrid backend; `FileLocator` (the provider-neutral handle for a media file) and its `resolve_url`/`invalidate` primitives; startup provider selection (`choose_provider`); test-only `MockProvider` |
| `rd_client.rs` | Real-Debrid implementation of `DebridProvider`; shared adaptive rate limiter, 1-hour unrestrict cache |
| `torbox_client.rs` | TorBox implementation of `DebridProvider` (`mylist`/`requestdl`/`createtorrent`/`controltorrent`); resolves by `(torrent_id, file_id)`, ~3h URL cache |
| `ratelimit.rs` | Shared `AdaptiveRateLimiter` (token bucket) used by both provider clients |
| `identification.rs` | Filename cleaning, camelCase splitting, TMDB scoring to identify movies/shows |
| `vfs.rs` | In-memory virtual filesystem: creates `Movies/`+`Shows/` hierarchy with media files and NFO metadata. `build` consults the injected `SelectionMap` (slot → `{hash, file_path}`) to pick the representative file per title/episode; falls back to largest-bytes for slots with no managed selection, so external/un-managed/pre-SP3 torrents behave exactly as before. |
| `dav_fs.rs` | Maps VFS to WebDAV; on read resolves a `FileLocator` to a CDN URL via `provider.resolve_url` (cached 1h), attempts synchronous instant repair on `AppError::Unavailable` (resolve-time) or a persistent CDN **5xx** (byte-fetch time, via the shared `attempt_instant_repair`). The byte fetch is **window-bounded**: it reads only the requested `[pos, range_end]` window then drops the connection, so a Range-ignoring CDN that replies `200 OK` streaming the WHOLE multi-GB object from byte 0 (**TorBox**; Real-Debrid replies `206`) is accepted at `pos == 0` and serves correctly — it is NOT rejected as "oversized" on its full-file `Content-Length` (mirrors `probe::read_body`). A `200` at any `pos > 0` is still rejected (it would be the wrong bytes), as is a `206` whose `Content-Range` start disagrees with `pos`. |
| `repair.rs` | Torrent repair state machine (Healthy→Broken→Repairing→Failed); provider-neutral instant repair — `try_instant_repair(&FileLocator)` re-adds by hash and, if cached, returns a fresh `FileLocator` for the same file (matched by `file_path`) for `dav_fs` to swap in (30s cooldown, max 3 attempts) |
| `tmdb_client.rs` | TMDB search for movies and TV shows; also exposes `show_status` (Ended/Returning/Other), per-season episode air dates, and season enumeration — feeding the SP2 episode monitor + finish lifecycle |
| `store.rs` | `Store` — owns all redb table definitions, schema **v7** + migration hook, `open()` with auto-recovery (moves an unreadable/incompatible DB aside and recreates it), and typed async accessors for: `matches` cache, `owned_hashes`, `authoritative_ids`, `blacklist` (keyed by `(media_type, tmdb_id, hash)` — a movie and a show sharing a numeric TMDB id keep independent rejection histories, like every other table; TTL-pruned — `prune_blacklist_before` is called from the scan loop on startup + ~daily with a 30-day TTL so the otherwise append-only table can't grow unbounded; a rejected hash also becomes retryable again after the TTL), `trakt_tokens` + `wanted` (SP2), and (SP3) the `selection` table (slot → `{hash, file_path}`) and `upgrade_checks` cursor. `OwnedRecord` carries per-user `Provenance` and (SP3) `provides: Vec<(season, episode)>` — the episodes this hash supplies — and `quality: Option<QualitySummary>` — compact release snapshot for upgrade comparison. |
| `scraper.rs` | `Scraper` trait + `TorrentioScraper` — calls a Stremio-compatible addon (default: Torrentio, auto-templated from the provider token) and parses stream objects into `RawCandidate` values. `build_http_client(proxy_url)` builds the scraper's reqwest client with an optional `SCRAPER_PROXY_URL` HTTP(S) proxy applied to scraper traffic ONLY (the CDN/probe/TMDB/provider clients stay direct); a non-http(s) proxy scheme is a hard startup error |
| `release.rs` | `RawCandidate` → `ReleaseInfo` parser (resolution, codec, HDR, size, seeders, cached flag, source tier); `score`/`rank` with quality prefs; hard-filters the resolution ceiling, cam/telesync/screener sources, **and uncached zero-seeder releases** (quality/availability floor), then ranks by **resolution within the ceiling** (dominant), then source tier (REMUX>BluRay>WEB>HDTV), then bitrate. `is_meaningful_upgrade` follows the same `score` ordering (strict score gain + a tier/resolution category jump) so upgrades stay consistent with acquisition and never flip-flop |
| `probe.rs` | Hand-rolled MKV/MP4 track reader; `probe_tracks` fetches the first 4 MB of a CDN URL and extracts audio/subtitle language codes; `verify` checks language requirements; corrupt/mismatch → blacklist, unknown → accept; a truncated/under-fetched ranged read → `Transient` (defer + retry, **not** blacklisted). The MKV parser caps the top-level **Segment** to the fetched buffer: a real Segment declares the size of the WHOLE (multi-GB) file, far beyond the 4 MB front read, so its declared end is matched **before** the overrun guard — otherwise the probe wrongly deferred (`Transient`) on essentially every large MKV. The front (offset-0) fetch accepts a **`200 OK`** as well as `206` — a CDN that ignores the `Range` header and streams from byte 0 (**TorBox** does this; Real-Debrid replies `206`) still yields the first window; we read up to `FRONT` bytes then drop the connection. Requiring `206` made every TorBox probe defer forever even though playback worked (`dav_fs::fetch_cdn_range` already accepted the offset-0 `200`). The suffix/tail fetch still requires `206` (a `200` returns the head, not the tail). |
| `reacquire.rs` | `materialise` — re-adds a torrent by hash, **polls** for the file list (retrying every `settle` up to a caller-set `max_wait`, so slow-to-resolve uncached metadata isn't given up on after one check), and selects the target files. Used by the **instant-repair path only** — the SP3 acquisition engine no longer materialises (it adds optimistically in `acquire` and resolves the verdict in `observe`) |
| `read_activity.rs` | In-memory proxy read-activity tracker (SP3). `ReadActivity::touch(path)` is stamped by `dav_fs` on every proxy byte read; the upgrade engine calls `all_idle(window)` — a library-wide check (if ANY path was read within the window the upgrade tick is deferred) — before swapping/pruning. `is_idle(path, window)` also exists but is not what gates swaps. Best-effort in-memory only: after a restart everything is idle. |
| `acquire.rs` | `AcquisitionEngine` — **optimistic `acquire`** (SP3): scrape → rank → add the best non-blacklisted candidate → best-effort `select_files` for an already-cached add → record `Pending` → return immediately (no synchronous validation/probe; the verdict is deferred to `observe`). **`observe`** is the resolver (every scan tick): once files resolve, runs the deferred pack-guard → strict title-validation → probe; on pass — marks `Verified`, records `provides` (which episodes the hash supplies) + `quality`, writes `selection` entries; on fail — blacklists hash → re-scrapes → next candidate. Reaps genuinely-dead torrents after `ACQUIRE_DEAD_TIMEOUT_SECS` (default 600s). Stall detection (`STALL_TIMEOUT_SECS`) is preserved. A probe that keeps coming back **`Transient`** (CDN momentarily unavailable) is re-probed every tick for the first `MAX_VERIFY_ATTEMPTS`, then on a `VERIFY_BACKOFF` (1h) cadence — it is **never accepted unverified** (so a wrong-language release can't freeze into the library); if still unfetchable past `VERIFY_DEADLINE_SECS` (24h, anchored on the persisted `added_at`) it is treated as effectively broken and replaced (blacklist + re-acquire). |
| `error.rs` | Unified error type (`AppError`) using `thiserror` |
| `jellyfin_client.rs` | Optional Jellyfin notification client — notifies Jellyfin of changed paths via `POST /Library/Media/Updated` |
| `trakt_client.rs` | `TraktClient` trait — device-flow OAuth (`device_code`/`poll_token`/`refresh`), reads (`watchlist`/`in_progress`/`watched`), `show_progress` (per-show `progress/watched` → `ShowProgress{aired,completed,behind}`, the precise catch-up "behind?" gate), and `me()` for the user slug — plus `TraktClientImpl` (shared adaptive rate limiter, Trakt headers) and test-only `MockTrakt`. `WatchedShow` carries the show's Trakt numeric id (`trakt_id`) so `show_progress` can be called |
| `wanted.rs` | PURE reconcile-core (zero I/O): `reconcile_title`/`reconcile` + lifecycle predicates (`wants`, `user_finished`, Trigger A `trigger_a_finished`, Trigger B `trigger_b_abandoned`, `should_remove`); types `TitleView`/`Owned`/`Action` |
| `scheduler.rs` | `periodic` primitive + `run` that spawns the cooperating periodic jobs over `AppState`; the Trakt cycle + episode monitor are gated on `trakt_jobs_enabled` |
| `enrolment.rs` | Local-network Trakt device-flow enrolment page (`/trakt/accounts`; enrol/refresh/remove) served on the WebDAV listener; `poll_to_completion` stores tokens keyed by Trakt user slug |
| `upgrade.rs` | Daily quality-upgrade + full-season consolidation engine (SP3). `run_upgrade_once` processes owned titles in a round-robin budget (`UPGRADE_BUDGET_PER_TICK`): for movies — scrapes, finds a meaningfully-better CACHED release (`is_meaningful_upgrade`: uncached→cached, OR a strict `score` gain on a concrete category jump — higher resolution, or a higher source tier at the same resolution — never trading resolution for tier, so it stays consistent with acquisition and can't flip-flop), stages it, and idle-gated swaps the `selection` + prunes the superseded torrent; for shows — finds a CACHED full-season pack covering all aired episodes at same-or-better quality (`consolidation_target`), stages it, and on idle-gated success repoints all episode `selection` slots and prunes scattered episode torrents. |
| `mapper.rs` | Library root — module declarations + the crate-canonical `now_unix_secs()` epoch-seconds helper (re-used by `acquire`/`upgrade`/`tasks`) |

**Data flow for playback:**
1. Jellyfin/player opens a media file via WebDAV
2. `dav_fs.rs` resolves the file's `FileLocator` to a CDN URL via `provider.resolve_url(&FileLocator)` (cached). Real-Debrid resolves via the locator's restricted `link` (1h cache); TorBox resolves by `(torrent_id, file_id)` via `requestdl` (no per-file link; ~3h cache).
3. `ProxiedMediaFile` fetches bytes from the CDN URL with a 2MB read-ahead buffer and serves them to the player

**Persistence:** Embedded `redb` database (`metadata.db`) caches TMDB identifications. The file is created automatically on first run. All `redb` access goes through `store.rs` (the `Store` type); modules never open transactions inline.

## Key Design Decisions

- **Provider abstraction:** All components depend on `Arc<dyn DebridProvider>` (defined in `provider.rs`) rather than a concrete client. `RealDebridClient` and `TorBoxClient` are the two implementations; exactly one provider is active per deployment, chosen at startup by `choose_provider` based on which token (`RD_API_TOKEN` or `TORBOX_API_KEY`) is set.
- **TorBox specifics:** TorBox lists torrents (with files inline) via `mylist`, resolves a file by `(torrent_id, file_id)` via `requestdl` (so `FileLocator.link` is `None`), re-adds by hash via `createtorrent`, deletes via `controltorrent`, and treats `select_files` as a no-op (TorBox auto-selects). A finished download is normalised to `status = "downloaded"` even when its cache has lapsed (TorBox keeps such entries listed as Inactive), so owned-but-uncached films still appear in the library and re-acquire on playback. TorBox's `progress` (a `0.0–1.0` fraction) is mapped to the canonical `Torrent.progress` as a `0–100` percentage (matching Real-Debrid) so the acquisition engine's stall detector — which resets only on a progress *change* — sees a moving signal for an actively-downloading uncached torrent (without it, `progress` stayed a constant `0.0` and a legitimate download was falsely reaped + blacklisted after `STALL_TIMEOUT_SECS`). The `mylist` response is parsed defensively: per-torrent fields TorBox sends loosely — `size: -1` (metadata not yet resolved) and `files: null` — are tolerated (signed sizes clamped to 0, null fields defaulted) so one malformed entry cannot fail the whole decode and hide the entire library.
- **Provider-neutral file resolution:** The VFS stores a `FileLocator { hash, torrent_id, file_id, file_path, link }` per media file rather than a raw RD link. `resolve_url(&FileLocator) -> Result<String, AppError>` is the single resolution primitive (and `invalidate(&FileLocator)` drops a cached resolution); RD resolves via the locator's restricted `link` (keeping its old unrestrict/cache logic as private inherent methods), while `(torrent_id, file_id)` is used by providers without per-file links (TorBox). `AppError::Unavailable` is the provider-neutral "bytes not currently available → re-acquire/repair" signal — RD maps any 5xx on unrestrict to it, and `dav_fs` drives instant repair off `Unavailable` rather than inspecting an HTTP status. Real-Debrid behaviour is unchanged.
- **Static linking / scratch Docker image:** The Dockerfile builds with musl targets (`x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`) producing a minimal final image on `scratch`.
- **Adaptive rate limiting:** An `AdaptiveRateLimiter` (token bucket, capacity 1, in `ratelimit.rs`) is shared across a provider's API calls — both `RealDebridClient` and `TorBoxClient` use it. Baseline: 10 req/s (100ms interval). On 429: interval doubles (max 30s under sustained throttling) and `Retry-After` is respected. On success: interval **halves** toward baseline (multiplicative recovery, min 100ms) so a bulk throttle burst doesn't leave later requests crawling at the raised ceiling. **TorBox additionally paces proactively:** `send_data`/`send_ok` read `x-ratelimit-remaining`/`-reset` from every response and call `observe_rate_limit`, holding the next request until the window resets when it is nearly spent — so bulk acquisition stays under TorBox's ~60/window `createtorrent` limit instead of storming into 429s. Real-Debrid sends no rate-limit headers (confirmed live), so it stays on the reactive MIMD path (multiplicative-increase on 429, multiplicative-decrease on success — see `ratelimit.rs`). RD signals throttle as a bare `429` (`error_code 34`, no `Retry-After`); separately, **any 5xx** on `unrestrict/link` (503 is RD's `hoster_unavailable`, `error_code 19`; 500/502/504 are infra errors) is a terminal status (no retry) — this is the synchronous on-read playback path, so it must fail fast rather than run the full ~10-attempt backoff (~3 min) that would surface to the player as a hang. `resolve_url` maps it to `AppError::Unavailable` → on-demand repair.
- **Per-client retry helpers:** `rd_client.rs` has one `fetch_with_retry(make_request, terminal_statuses)` — callers pass the status codes that should abort without retrying (e.g. 404 for `get_torrent_info`, the full 5xx set — 500/502/503/504 — for `unrestrict_link` so the playback resolve path fails fast to repair). `torbox_client.rs` has `send_data`/`send_ok`, which rate-limit, retry on 429/transient errors, and unwrap TorBox's `{success, detail, data}` envelope.
- **Identification scoring:** `identification.rs` cleans filenames extensively before TMDB lookup. Shows vs. movies are detected by file structure (presence of multiple video files with episode patterns).
- **Synchronous instant repair (provider-neutral):** When a media file is read, `dav_fs.rs` resolves the locator via `provider.resolve_url` (cached, so free when healthy). On `AppError::Unavailable`, it calls `repair_manager.try_instant_repair(&FileLocator) -> Result<FileLocator, _>` synchronously — re-adds the torrent by hash, selects the same files, and checks if the replacement is already cached. Success is decided by the new torrent reaching `status == "downloaded"` **plus** a `file_path` match for the same file (there is no `InstantRepairResult` type, and no RD-specific link-count check — path matching is inherently safe, and the replacement file is located by matching `file_path` rather than the old positional index into RD's `links` array). On success it returns a fresh `FileLocator` for that file — pairing the per-file restricted `link` by position among selected files for RD, or leaving `link: None` for providers that resolve by `(torrent_id, file_id)` (TorBox). `dav_fs` installs the returned locator (invalidating the old resolution) and re-resolves inline, so playback continues after a brief delay. If **not** cached on a genuinely-new id (RD), the file fails, the new torrent is left to download, the old torrent is marked Broken, and the replacement is recorded (scan loop picks it up). **Same-id re-add (TorBox):** TorBox's `createtorrent` recovers the existing torrent by infohash, so a repaired-in-place torrent keeps its **same** id (`new == old`); the repair therefore never deletes it (deleting would destroy the very torrent it repaired — and for mirror/manual content that would be permanent loss), records no replacement, and passes `protect_id` to `reacquire::materialise` so a transient post-add failure can't delete the real torrent either. **Visible on no-replacement failures:** a repair that produces no usable replacement (a transient re-add/info error, or a same-id torrent that's merely re-downloading) leaves the torrent **`Healthy`/visible**, NOT `Broken` — because `read_bytes` short-circuits on `should_hide_torrent` *before* any I/O, a hidden torrent can never re-trigger repair, so marking it Broken with no replacement would trap it until restart. `Broken` is set ONLY where a replacement IS recorded (the not-cached new-id path). **Cooldown + attempt cap survive re-adds:** the repaired torrent's health carries the old entry's `repair_attempts` plus a fresh cooldown trigger to the new id (RD mints a new id each repair), so the 30s cooldown + max-3-attempt cap hold *across* re-adds — bounding a still-broken-on-CDN cached file to ≤3 re-adds rather than a per-read storm. A confirmed good byte read (`note_read_success`, called once per opened file) **resets** the budget, so the cap counts only *consecutive* failed repairs (a storm), not unrelated incidents over the deployment's lifetime (which would otherwise accumulate to a permanent `Failed`).
- **Repair hides broken torrents (provider-dependent):** On the not-cached repair path with a genuinely-NEW id (Real-Debrid), the old torrent is marked Broken and hidden from WebDAV until the scan loop picks up the recorded replacement. On a SAME-id re-add (TorBox's `createtorrent` recovers the existing torrent by infohash), and on any repair failure that records NO replacement, the torrent is instead kept `Healthy`/visible — because a `Broken`/hidden torrent can never re-trigger repair (reads short-circuit on `should_hide_torrent`), so hiding it with no replacement would trap it until restart (see the instant-repair design decision below).
- **SP1 Acquisition Engine (historical — superseded by the SP3 optimistic-add model below; `acquire` no longer materialises/validates/probes synchronously, it adds the best candidate and defers the verdict to `observe`):** When a title is requested (by the SP2 Trakt reconciler — `reconcile_wanted`/`monitor_episodes` — which replaced the temporary `--acquire` CLI), the engine originally ran: (1) **Scrape** — `TorrentioScraper` calls a Stremio-compatible addon (default: Torrentio, URL auto-templated from `<provider>=<token>`; override with `SCRAPER_ADDON_URL`). (2) **Score/rank** — `release::parse` extracts resolution, codec, HDR, size, seeders, cached flag, and source tier; `release::rank` hard-filters the resolution ceiling (`MAX_RESOLUTION`), cam/telesync/screener sources, **and uncached zero-seeder (undownloadable) releases** (so the engine never burns acquire attempts on dead torrents or leaves "checking" magnets behind), then sorts by a weighted score: cached availability dominates, then **resolution within the `MAX_RESOLUTION` ceiling** (a user who raises the ceiling to 2160p wants 4K, so resolution outweighs source tier), then source tier [REMUX>BluRay>WEB>HDTV], then progressively smaller **additive** bonuses — HEVC (+5k), HDR (+3k), verifiable container (+2k), bitrate (up to +3k), seeders (up to +2k) — which **combine into the weighted sum rather than forming a strict tie-break chain** (e.g. the HEVC bonus can outweigh a one-step source-tier difference, and bitrate can outweigh the container bonus), with a configured-`AUDIO_LANGUAGE` mismatch applied as a large penalty; see `release::score` for exact magnitudes. (3) **Materialise** — re-adds the torrent by hash, waits for the file list, and selects the target file; **a movie request whose materialised torrent has more than one feature-sized video is rejected as a multi-movie pack** (providers like TorBox auto-select all files). (Post-SP3 only `repair.rs` calls `reacquire::materialise`; `acquire`/`observe` add optimistically.) A candidate whose materialise *fails* (provider "already queued", or an add whose file list never resolves) has any leaked torrent for its hash deleted before the next candidate is tried, so a rejected/failed candidate never lingers as a dead "checking" torrent. (4) **STRICT title validation** — `TmdbTitleValidator` runs `identify_name` on the selected file's name and verifies the result resolves to the requested TMDB id; mismatches are blacklisted and the next candidate is tried. (5) **File-probe** — `HttpProber` fetches the first 4 MB of the CDN URL and uses the hand-rolled `probe::probe_tracks` (MKV/MP4) to extract audio/subtitle language codes; corrupt probes are blacklisted, wrong-language probes are blacklisted, unknown formats are accepted. (6) **Outcome** — `Acquired` (cached + verified), `Pending` (downloading or probe deferred), `NoAcceptableRelease`, or `TemporarilyUnavailable`. `observe` monitors Pending torrents each scan tick: stall detection (no progress for `STALL_TIMEOUT_SECS`), deferred probe retry (up to `MAX_VERIFY_ATTEMPTS`), and fail-and-reacquire. The `authoritative_ids` table overrides filename identification for engine-owned torrents; the `blacklist` table prevents re-adding rejected hashes.
- **Trakt-driven desired state (SP2):** A persisted `wanted` set (per user, per **(media_type, tmdb_id)** — so a movie and a show that share a numeric TMDB id are tracked independently; which sources want it — watchlist / in-progress — plus watched-state and, for shows, TMDB status, **and the IMDB id Trakt supplied**) is materialised from each enrolled user's Trakt account by `sync_trakt`. **Catch-up source:** a show you've *watched* (from `/sync/watched/shows`) is also folded into the wanted-set as an in-progress source — so episodes that aired since you last watched are auto-acquired — gated by `TRAKT_CATCHUP_LOOKBACK` (last-watched within the window; default all-time) and skipped when the show is already watchlisted (the watchlist already wants its whole run). The catch-up membership is **precisely gated on Trakt per-show progress** (`GET /shows/{trakt_id}/progress/watched`): a within-lookback watched show is folded in **only if Trakt reports it has ≥1 unwatched aired episode** (`next_episode` non-null = behind), so fully-caught-up shows don't bloat the wanted-set or drive a fruitless reconcile each cycle. The progress check runs in `sync_trakt_user` (one call per catch-up candidate; on a missing Trakt id / progress error it conservatively includes the show — degrades to lookback-only rather than dropping a possibly-behind title) and is passed to the PURE `build_wanted` as the fold set. **Finish-cleanup fold:** a caught-up (not-behind) watched show that is **owned AND `Ended`** is a finish-removal candidate; `sync_trakt_user` LOGS these every sync (a preview) and — **only when `REMOVE_FINISHED_SHOWS` is set** — also folds them into the wanted-set so the reconciler's Trigger-A finish removal fires (the acquire path acquires nothing — every episode is watched). When the flag is off they're preview-only and never folded, so nothing is removed. `finished_ended_candidates`/`shows_to_fold` are the pure helpers. A catch-up show acquires only the **unwatched** aired episodes (you want what you haven't seen); a **watchlisted** show acquires **every** aired episode (the whole run, even already-watched, for a re-watch); and `reconcile_title`'s Show branch won't acquire a show all watchers have *finished* (symmetry with Trigger A — a watchlisted show is never "finished", so it still acquires). **IMDB resolution prefers Trakt's id** (`WantedRecord.imdb_id`, carried through to the `Acquire` op) over re-deriving it from TMDB's `external_ids`, because TMDB's mapping is incomplete for some titles (e.g. a TVDB-only show) — `build_acquire_request` falls back to TMDB only when Trakt gave none, and returns `Ok(None)` (skip quietly, logged at debug — Torrentio is IMDB-keyed so it can't be scraped) when no IMDB id exists anywhere, rather than WARN-ing every reconcile tick. A PURE reconcile-core (`wanted.rs`) diffs wanted-vs-owned-and-available and emits acquire/remove `Action`s, executed by `reconcile_wanted` (movies + show Trigger-B removal) and `monitor_episodes` (show episode acquisition + Trigger-A finish removal, via TMDB air dates). There is **one shared household library**: acquisition is the union across users; removal is per-user-aware.
- **Removal lifecycle:** Only engine-owned torrents are ever removed (manual adds are never auto-removed — `Provenance::has_manual_entry` guards). **Trigger A (finished):** every user who **in-progresses** the title has finished it (movie watched; show = 100% of *aired* episodes watched AND its TMDB status is `Ended` (ended or cancelled — `ShowStatus::Ended`; a returning/in-production/planned show never qualifies even if fully watched)). **A watchlisted title is NEVER finished-removed** — the watchlist is an explicit "keep this available" signal (re-watchlisting something you've watched means you want to re-watch it), so it stays acquired regardless of watched state and `trigger_a_finished` short-circuits to `false` while any user watchlists it. Without that guard a watched+watchlisted title oscillated acquire↔remove every reconcile tick (the acquire path ignores watched), flapping the library. **Trigger B (abandoned):** a watchlist-provenance user un-watchlisted it AND no user currently wants it (via either source) — this is the sole removal path for a watchlisted title. Otherwise the title is kept. Provenance is **sticky** — recorded at acquire time (one entry per wanting user+source) and preserved across re-acquire, including any `Manual` entry. Both removal triggers are executed through the **idle-gated** `execute_remove` (`UPGRADE_IDLE_SECS`), so a removal never tears content out from under an active stream (a non-idle library defers the removal to a later tick, leaving the owned record intact for retry).
- **Availability re-acquire:** A wanted title that is owned but no longer present in the provider listing is treated as lapsed (cache expired / lost) → proactively re-acquired (movies and per-episode for shows).
- **Account mirror = owned (no protected "manual" class):** The scan loop's `record_mirror_owned` records every identified, present provider torrent the engine doesn't already track as a **`Verified` owned record with EMPTY provenance** (a show's `provides` = the SE-parsed set of its selected video files; a movie's is empty; `quality` is **derived from the representative/largest video file** — `cached: true` since it is present — so the record is comparable on the upgrade/consolidation path, or `None` when there is no video file, the file is above the resolution ceiling, **or its filename doesn't tag both the resolution AND the source tier** (an unknown axis would let an "upgrade" silently downgrade it), in which case the upgrade path skips it conservatively; `imdb_id` resolved from TMDB `external_ids`, cached per-title, best-effort). This makes the reconciler/episode-monitor aware of the user's **pre-existing library**, so a watchlisted/in-progress title that is already present is **not re-acquired as a duplicate**, and a pre-existing season pack reports its episodes as owned (no per-episode `monitor_episodes` churn). Empty provenance means the record is owned **exactly like an engine-acquired title** — eligible for the daily quality-upgrade / consolidation path (deliberately NOT a `Manual` protected class, so manually-added content follows the same upgrade path) — while still being **kept** under the normal lifecycle: with no Trakt wanter and no watchlist provenance, neither removal trigger (`trigger_a_finished`/`trigger_b_abandoned`) fires for a mirror-only group, and Trigger **B** (abandoned watchlist) never deletes a mirror hash even when it shares a `tmdb_id` with watchlist-acquired episodes (removal is scoped to the group's engine-acquired hashes — `OwnedGroup.engine_hashes` — via `removal_hashes`). It is idempotent and non-destructive — an engine-owned or already-mirrored hash is never clobbered. `observe`'s dead-torrent re-acquire skips only records with **no IMDB id** (can't re-scrape → leave for on-read repair), not by provenance. **A mirror hash (empty provenance) is protected from the general Trakt removal lifecycle**, even when a Trakt user *wants* the title (it shares the `tmdb_id`): a genuine in-progress re-watch (the title is in `/sync/playback` AND already watched) must never delete content the engine didn't acquire. `removal_hashes` enforces this — for a `Finished` (Trigger A) removal it returns only the group's **engine-acquired** hashes (`OwnedGroup.engine_hashes`) EXCEPT in the one opt-in case: a **show** with `REMOVE_FINISHED_SHOWS=true`, where the finish-cleanup *folds* fully-watched ended owned shows into the wanted-set specifically to reclaim the full set (incl. pre-existing library copies). Trigger **B** (abandoned watchlist) also returns only engine hashes. So a mirror torrent is removed only by (a) the explicit duplicate-dedup pass, (b) `REMOVE_FINISHED_SHOWS=true` show finish-cleanup, or (c) when it is *also* engine-acquired (mixed group) and that engine hash is reclaimed. A pure-mirror **movie** is never finish-removed (movies are never folded). `reconcile_title`'s symmetric acquire-side guard (both the Movie and Show branches short-circuit on `trigger_a_finished`, except for manual content) means an engine-reclaimed title is **not** re-acquired the next tick — no acquire↔remove flip-flop; to keep a watched title available, watchlist it.
- **Multi-user enrolment:** Accounts are linked via device-flow OAuth on the local-network enrolment page (`/trakt/accounts`, served on the WebDAV listener — no auth, trusted-LAN model). Tokens are keyed by Trakt **slug**. A token-refresh or read failure marks the account `needs_reenrolment` (surfaced on the page) and leaves its prior `wanted` set intact — the reconciler never acts on a failed fetch.
- **`--acquire` CLI removed:** The temporary SP1 verification CLI was deleted in SP2; Trakt sync + the reconciler are the acquisition triggers now. A `scheduler.rs` source-guard test (`acquire_cli_is_removed`) fails if the flag is reintroduced into `main.rs`.
- **Database is self-healing (but only for genuine corruption):** `Store::open` stamps a schema version and runs forward migrations. A genuinely corrupt / incompatible / newer-than-binary `metadata.db` (e.g. after a `redb` format change, or a bad-header `Io(InvalidData)`) is **moved aside** to `<db_path>.corrupt` and recreated rather than crashing the service. The `matches` table is a regenerable cache, so this is lossless in practice; authoritative tables added in later phases are migrated, never silently dropped. A **transient/operational** open failure — another instance holding the lock (`DatabaseAlreadyOpen`), a permission/disk I/O error — is classified separately (`db_open_failure`) and **fails startup** instead of discarding a possibly-intact database.
- **SP3 — Optimistic-add + asynchronous reconcile (always-on robustness + daily quality):** `acquire` now **adds the best candidate optimistically** and records it `Pending` — no synchronous 15s poll, pack-guard, title-validation, or probe. `observe` (every scan tick, no scraping) is the resolver: once files appear, the deferred gates run; on pass it marks `Verified`, records `provides` (which `(season, episode)` pairs the hash supplies) and a `quality` summary, and writes `selection` entries; on fail it blacklists the hash and re-scrapes for the next-best candidate. Genuinely-dead torrents (provider error status, or no resolution after `ACQUIRE_DEAD_TIMEOUT_SECS`) are reaped and re-scraped. **Selection inversion:** "which release represents this title/episode" is a persisted `selection` table (slot → `{hash, file_path}`) that `vfs::build` consults on every scan; a largest-bytes fallback preserves pre-SP3 behaviour for un-managed torrents. **`provides` kills season-pack churn:** the union of `provides` across a show's owned hashes is the owned-episode set — a season pack reports all its episodes as owned so `monitor_episodes` never re-acquires them. **Daily upgrade engine** (`upgrade.rs`, on by default, disable with `UPGRADE_INTERVAL_SECS=0`): re-scores owned titles in a round-robin budget and stages a meaningfully-better CACHED release (uncached→cached, or a strict `score` gain on a resolution/tier category jump — consistent with acquisition's ranking, never trading resolution for tier); idle-gated swap (`UPGRADE_IDLE_SECS`) + prune of the superseded torrent ensure an active stream is never interrupted. **Full-season consolidation:** the same engine finds a CACHED full-season pack covering all aired episodes at same-or-better quality and consolidates scattered per-episode torrents into it, idle-gated.

## Development Process

- **Test-Driven Development (TDD) is required.** When implementing new features or fixing bugs:
  1. Write a failing test first that captures the expected behavior.
  2. Write the minimum code to make the test pass.
  3. Refactor while keeping tests green.
  4. Run `cargo test` after every change to confirm nothing is broken.
- **Before every commit, run the lint gate (this is CI's `lint` job — fmt + clippy):**
  ```bash
  cargo fmt --check && cargo clippy --all-targets -- -D warnings
  ```
  CI runs these on the latest stable Rust (`dtolnay/rust-toolchain@stable`), and each new stable
  can add clippy lints — so keep your local toolchain current (`rustup update stable`), otherwise
  lint can pass locally yet fail in CI on a lint your older clippy doesn't have. If
  `cargo fmt --check` fails, run `cargo fmt` to fix; do not hand-format around it.
- **Before every commit, run all unit and integration tests:**
  ```bash
  cargo test \
    && INTEGRATION_TEST_LIMIT=10 cargo test --test integration_test -- --ignored \
    && INTEGRATION_TEST_LIMIT=10 cargo test --test repair_integration_test -- --ignored \
    && cargo test --test lifecycle_test -- --ignored
  ```
  Integration test binaries must run sequentially (not `-- --ignored` on all at once) because they share the redb database lock and the Real-Debrid API rate limit. Do not commit if any test fails. (CI and the Docker build run with `--locked` — if you bump `Cargo.toml`, run `cargo test --locked` / `cargo build --locked` locally too so a stale `Cargo.lock` is caught before CI rather than silently updated.)
  - `lifecycle_test` is the cross-provider add→appears→delete→disappears check, plus a `lifecycle_acquire_sintel_by_imdb` test that exercises the SP1 `AcquisitionEngine` end-to-end against the live provider. It runs against **both** Real-Debrid and TorBox, **modifying the live account** (adds and deletes a Creative-Commons *Sintel* torrent, cleaning up after itself). Each provider's sub-test **skips** if its token (`RD_API_TOKEN` / `TORBOX_API_KEY`) is unset, so it is safe to run with only one provider configured.
- **Integration tests must be updated for new functionality.** When adding or changing features, update the integration tests to cover the new behavior. Integration tests are the final gate before committing.
- **Additional integration test files** (all `#[ignore]`, require API tokens): `test_all_rd_torrents.rs`, `test_identification_stats.rs`, `test_short_titles.rs`, `test_media_generation.rs`, `video_player_simulation.rs`, `trakt_smoke_test.rs`, `sp1_live_test.rs` (live Torrentio scraper smoke, incl. `scraper_live_through_http_proxy` which validates `SCRAPER_PROXY_URL` against a real proxy — negative control + positive case, the latter skipped when the proxy isn't routable), `probe_integration_test.rs` (probes a cached *Sintel* file through BOTH providers' CDNs — asserts the probe reaches a verdict without deferring, guarding the 206/200 range-response handling; runs RD + TorBox, each skips if its token is unset, cleans up after itself). These are supplementary and not part of the pre-commit gate.
- **Interactive Trakt live integration test** (`tests/trakt_integration_test.rs`): validates every Trakt parser and `sync_trakt` end-to-end against a real account without requiring a pre-existing token. Run with `cargo test --test trakt_integration_test -- --ignored --nocapture`; the test prints a URL + code, waits until you open it and approve on trakt.tv/activate, then exercises all reads and asserts the `wanted` set is populated. Requires `TRAKT_CLIENT_ID`, `TRAKT_CLIENT_SECRET`, and `TMDB_API_KEY`; skips cleanly if any is unset.
- **Before every commit, validate that `CLAUDE.md` and `README.md` are up-to-date.** If the commit introduces new features, env vars, modules, architectural changes, or modifies existing behavior, update both files to reflect the changes. Documentation must stay in sync with code at all times.
